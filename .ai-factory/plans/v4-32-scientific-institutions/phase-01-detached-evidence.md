## Task 1: Specify detached evidence and coverage

1. Define frozen `PracticeWindow`, `PracticeCoverage`, `PracticeExecutionFact`, `PracticeCarrierFact`, `PracticeOrganizationFact`, and `PracticeSupplementFact` in the new contract module. `PracticeWindow` carries run ID, window index and start/end-exclusive ticks; window `i` is `[32*i, 32*(i+1))`. An incomplete trailing window is reported but never qualifies. Use actual `boundary_tick`, not a generation number, revision or wall clock.
2. Separate objective receipts, owner-attributed organization/context assertions, and analytical associations in the types. Scientific practice key is the closed `(operator, process_token)` from an admitted deliberate `ExperimentResolved`. It describes a coarse activity family, **not** identical experimental conditions or replication.
3. Use one run-scoped digest namespace with explicit domains for actor, occurrence, carrier and source root. Resolve `AgentId` and `EntityId` via the boundary registration map **before** tokenization; use a separate namespace for owner-local IDs, qualified by owner. Preserve exact kind alongside token. Reject duplicate keys, namespace/kind mismatches, bool-as-int, invalid ranges, contradictory identities and cross-run joins. Canonical-sort tuples; never include content, runtime checkpoints, record marks, reading values, LLM data or global labels.
4. Coverage is per window per lane (`complete`, `unavailable`, `partial`); distinguish complete-empty from absence. Cap first release at 16 full windows (512 ticks), 64 owners per boundary, 128 organization contributions per detector window, 32,768 cumulative events per supplied boundary, 4,096 projected rows per window and 8,192 published rows total. Reject over-limit inputs atomically with a safe reason code; do not silently truncate qualifying evidence.

**Acceptance and tests:** `test_scientific_institutions_contract.py` checks exact types, interval endpoints, shuffled inputs, same raw string across namespaces, duplicate identities, and N/N+1 caps. No logging in value types; no payload-bearing validation errors. Source anchors: project rules and architecture’s versioned extension contract.

## Task 2: Project finalized receipts

1. Add `build_scientific_institution_windows` in `src/experiments/scientific_institutions_completed_run.py`. Accept `SimulationRunnerResult`, originating `SimulationRunnerConfig`, and ordered paired inputs from Task 10: a bounded projection of `FinalizedResearchBoundary` plus tick/revision-matched carrier inventory from `WorldEngine.detached_objective_facts()`. Verify against `runner_config_fingerprint` in `simulation.runner_serialization`. Collect event IDs and canonical per-event hashes for prefix verification; retain only typed projected receipt fields, boundary identities and required context, not raw owner snapshots or full event payloads between ticks. Reject mismatched run/config identity, duplicate or decreasing boundary ticks, regressing revisions, boundaries beyond the result, and unfinalized/failed attempts. Never reopen/resume runs to reconstruct missing owner boundaries.
2. Use boundary `N` only for activity in `[N-32,N)`, with no lookahead from later owner snapshots. Build the expected window grid even if a supplied endpoint is missing. Validate cumulative event coverage against `SimulationRunnerResult.finalized_tick_receipts`: one contiguous resulting-tick receipt per executed tick, event counts (including zero), matching boundary revision and identical event hash prefix across supplied exports. `export_finalized_research_boundary` filters events to `event.tick < boundary_tick`, so a tick-zero export is **not** a reliable bootstrap-event baseline: inspect `runner.engine.export_events().events` at initialized boundary zero separately and subtract only the exact matching baseline IDs/hashes if present in later windows. Initial facts establish existence, not service. Unsupported flag combinations are unavailable; missing captures mark affected lanes unavailable, and a terminal tail shorter than 32 ticks is partial, never eligible.
3. Harvest admitted `ExperimentResolved` with `discovery_mode == "deliberate"` once per committed event ID; unsuccessful/refused commands and accidental discoveries do not count. Keep null or contradictory experimental outcomes eligible if execution itself was admitted; do not export outcomes in this slice. Harvest record creation/annotation and committed deposit/retrieval as practice carriers only for durable artifact IDs or a repository with an exact durable-member receipt. Confirm IDs/kinds from committed history. Keep `ArtifactCopied` parent/child references separate from fresh service actions; a copy does not generate an independent source root. Exclude destroyed carriers after destruction, and preserve failed provenance as unresolved, never as successful custody.
4. Debug log fixed window codes, counts and numeric bounds at composition; warn once on invalid export/cap with safe reason code, no raw IDs or evidence. Projection/capture failure may fail or disable publication, but must not change commands, results, or committed history.

**Acceptance and tests:** `test_scientific_institutions_completed_run.py` covers exact boundaries, wrong run/config, same-ID changed-hash prefix, a bootstrap event sharing tick zero, missing endpoint, complete-empty, no future snapshots, accidental/executed-null cases, duplicate event IDs, invalid entity mapping and destroyed/opaque records. Phase 4 uses actual in-process runner events; unit fixtures use typed event details. Run `uv run --frozen --python 3.12.14 pytest tests/unit/test_scientific_institutions_{contract,completed_run}.py -q`.

## Task 3: Project organization context and optional practice signals

1. At each valid endpoint call `harvest_organization_rows` with detached ledgers from owner checkpoints. For each window, keep only raw owner rows with last evidence in that window; filter nested rows to matching owner/local concept, remove expired membership, and run the existing candidate detector/identity assignment over these ordered `OrganizationWindowEvidence` inputs with inclusive end `end_exclusive-1`. Do not call the legacy whole-history window builder. In `organization_detection.py`, factor the existing detector body behind a shared implementation and add `detect_organization_candidates_with_contributors`, returning the original result plus canonical `(window_index, candidate_key, owner_id, local_concept_id)` tuples taken directly from `_contributions` at `_candidate_from_group`. The legacy entry point still returns the old result unchanged. Preserve exact attribution through union grouping; never reconstruct it from candidate member/owner unions. If duplicate candidate keys make attribution ambiguous, mark the affected organization window partial. Treat “resolved” owner anchors as claims, not committed witnesses.
2. For a candidate, use `(candidate_key, organization_id)` from existing assignment, checked against the candidate's window. Exact association requires a contemporaneous non-temporary `perceived`/`explicit` member row without a current `disputed`/`former` contradiction and an exact typed carrier anchor in its supporting concept, not another concept held by the same owner. In v1 the independently timed qualifying link is an accepted `ProjectContributed` by that actor in the same window, on a `collective_project` goal ID in that same local concept. Require the project witness before or at the practice action tick. The row's `last_tick` and sticky `independently_evidenced` bit do not independently date the witness; other membership bases without exact actor/anchor/tick provenance stay contextual. This restricts the research classifier, not the live organization model. Do not require a project for recording contextual signals. One receipt eligible for multiple same-window candidates is ambiguous and unassigned. Project procedure recurrence separately with opaque owner-qualified refs, never synthesize roots from counter text.
3. Use the existing institution concepts/office and institutional-memory checkpoints only for contextual corroboration: exact owner-local procedure or office relation, and where cross-layer material linkage is needed, exact typed record/repository ID. No name similarity or comparison of owner-local office/procedure IDs across owners. Preserve explicit support, disagreement and missingness; a stale or unresolvable row cannot validate an objective action. Schema or mode may be unavailable without invalidating the mandatory base lanes.
4. Produce separate candidate-linked supplements: experimenters and record keepers from constituent receipts; teachers from `SimulationRunnerResult.teaching_audits` (`ADVICE` only, source plus recipient and original delivery tick), joined to both uniquely linked participants; replication expectations from delivered invitation and acceptance at their observed ticks in `ReplicationLedger`, with linked child execution counted separately via `experiments.replication_completed_run.replication_facts` and exact execution witnesses; archives from admitted repository operations with a durable member. Shared use requires two eligible actors using the same `MeasurementTaken.reading.instrument_id` in a window; require both users uniquely map to the same candidate, and describe it as repeated shared use by its participants, not organizational ownership. `Measure` is not an experiment, separate holders don't prove sharing, and displays are not truth. No optional signal is a qualifying vote. Without an exact procedure/trial link, label teaching and tool use as contextual rather than proof of science-specific instruction or instrument use in a trial.
5. Debug log counts by lane and fixed omission reason; emit no private IDs or raw speech/marks. Mark an organization window partial if a required owner ledger is missing or a `history_truncated` notice prevents assurance for that window; no fallback to stale rows. Preserve enabled-but-empty ledgers as complete-empty. Owner-only failures in optional lanes mark those lanes partial; mandatory organization/input errors fail closed or mark the affected window unavailable, never complete-empty.

Add unchanged legacy detector-output parity. Run `uv run --frozen --python 3.12.14 pytest tests/unit/test_scientific_institutions_context.py -q`.

## Phase Risks and Mitigations

- Sidecar memory pressure: finite horizon, no automatic hooks; strip each bounded export at ingress and retain only detached facts plus necessary verified prefix identities. Do not present this as a long-horizon capture lane.
- Owner reports may look objective: keep claims and committed receipts in different DTOs; only exact typed joins produce an analytical association.
