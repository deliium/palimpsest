## Shared Captured Row Contract

- Common: row ID, evidence class, owner or null, exact boundary, window `[start_tick, end_tick)` ending no later than boundary, policy/version, coverage, source refs, zero or more typed anchors. Source content is not a UI label.
- `settlements` / ANALYTICAL: run+location stable candidate ID, location ID, eligible occupancy, infrastructure count, first/last supported boundary, observed streak, status. Policy `settlement-observer.v1`: candidate at B iff at least one living registered agent occupies the location at each of the four consecutive boundaries B−3…B and at least one intact structure exists at B. Missing boundaries censor; B<3 is insufficient evidence. Location identity remains stable across inactive periods; separate episode ordinal derives from absolute start boundary. This is a disclosed visualization heuristic, not a new metric family or settlement world object.
- `migration` / OBJECTIVE: journey ID, route endpoints, participants/count, phase or completed/ended outcome, actual ticks, event refs. Completed/ended history is derived from committed events, not absence from current journeys. Counts distinguish arrivals, starts, capacity waits and failed/ended journeys.
- `trade` / ANALYTICAL: completed-exchange count, item counts in each direction by exact kind, participants, occurrence location, window, event refs. Only `ExchangeCompleted` is exchange evidence. `Given`, `Take`, repository operations and carrying are separate transfer categories and never silently added to trade. No prices, currency value, trade routes or cross-region destination inferred from participants' present locations. Nonspatial bilateral relations remain nonspatial when event-time locations are absent.
- `culture` / ANALYTICAL: exact trait/representation identity, scope/basis, carriers, eligible living-owner denominator, unavailable-owner count, nullable proportion and evidence refs. Distinct traits are not merged by label. Per-location/region aggregation joins owner/body/location only at the same captured boundary; disclosed presence-based partition, not ethnicity or permanent residence. Require complete relevant coverage for a complete proportion; partial rows expose known counts plus unknown counts and null full-population proportion. Complete denominator zero gives null, not 0%.
- `technology` / SUBJECTIVE or ANALYTICAL: qualified practical-knowledge identity, holder/evidence status, acquisition boundary, source edge modality/attribution, living-holder denominator where applicable. Subjective scope is exactly one owner. Analytical diffusion requires retained attributable acquisition edges; communication delivery, matching labels or co-presence alone do not create diffusion. Unknown/ambiguous sources and independent rediscovery are separate rows/counters.
- `social_groups` / SUBJECTIVE or ANALYTICAL: owner-qualified native membership beliefs for selected owner, or `compute_candidate_communities` results with explicit interaction/residence basis and missing lanes. No global membership registry or continuity from matching colors. For empty living rosters return complete-empty directly: do not let the calculator infer a roster from stale edges.
- `institutions` / SUBJECTIVE or ANALYTICAL: owner-qualified concept/office status or existing institution lifecycle/lineage episode identity, evidence range, first/last supported boundaries, coverage, optional physical association. No objective institution rows, headquarters, borders or permissions. Disappearance requires confirmed status/episode transition in complete evidence; missing capture is a gap, not collapse.

## Task 4: Capture bounded finalized owner and physical evidence

### Intent

Retain precisely the evidence needed for historical overlays without enabling cognitive modes or changing simulation output.

### Implementation Steps

1. Add `SimulationRunner.set_civilization_boundary_sink` with install-once/before-start validation analogous to existing sinks. Add `_publish_initial_civilization_boundary` and `_publish_civilization_boundary_if_complete` and invoke beside the corresponding lineage publication sites in `run_tick`, `initialize_finalized_boundary` and `recover_pending_finalizations`, including generational recovery publication. Capture boundary zero after initialization and each fully finalized boundary, including successful recovery. Never publish between owners or before deferred subjective finalization completes. No sink means no additional export/copy work.
2. Define a metadata-only `CivilizationBoundaryInput`: detached physical location/registration bindings, current projects/repositories/structures/journeys, cultural owner inventories, selected fields from owner group/concept/office/decay/practical ledgers, typed event receipts and per-channel coverage. New `CivilizationEventReceipt` whitelists run/event ID, tick/sequence, event kind, participant/entity IDs, journey/project/repository/record IDs, item IDs/kinds/counts, outcome and event-time location/region IDs. Project inside simulation before calling the sink. Never retain raw `WorldEvent`, raw checkpoints, utterances, memories, full artifact/repository values with marks/index text, or arbitrary event detail mappings. Unrelated event bodies are examined only to account for source completeness and then discarded. New owner export helper returns detached immutable values; no new cognition state.
3. For physically grounded institutions retain `InstitutionGroundingWitness(owner_id, concept_id, evidence_id, evidence_tick, source_kind, source_id, location_id)`. Build only from the exact owner observation and matching native OBSERVED project/repository evidence produced in that invocation. Resolve the existing ordinal references against that same observation, with exact tick/channel/actor checks; retain the resolved typed source ID before observation is discarded. Never parse TESTIMONY/REMEMBERED refs, invert digests, match names or resolve ordinals against later observations. Missing exact observation on recovery means no witness. Witnesses label physical evidence association, not an institution's exclusive site.
4. Collect observations needed for those witnesses in an opt-in, tick-local detached staging area alongside prepare/finalize; release after finalized export or abort. Do not expose all-owner observations to cognition or outer callbacks. At recovery, preserve available native metadata but mark uncaptured grounding unavailable rather than reconstructing it from current state.
5. Separate `capture_events` from sampled `capture_boundary`. At every finalized tick collect/deduplicate receipts by `(run_id,tick,sequence,event_id)` and record an event-source high water, expected source-event count, examined count and contiguous covered tick intervals, even when snapshot cadence skips that boundary. Normally use the committed `TickResult` and its committed source count. On recovery, verify against `TickJournalRepository.get_tick_commit` and page `list_events` for the exact missing tick (limit200, hard total2,000 events/4MiB read for that recovery tick); compare count/order/identity before marking complete. An empty recovered TickResult is known-empty only when the journal proves zero events. Missing/incomplete journal or exceeded recovery-read budget records an explicit event gap, never a complete-zero window. Do not replay objective history or copy the whole engine event history on every tick. Event-time endpoints must be copied from committed occurrence context or the matching tick-local detached context, never later owner positions.
6. Recorder defaults: cadence1, max10,000 sampled boundaries, 1,000,000 retained rows/receipts and256MiB canonical buffered evidence/run, including institution samples/grounding. Check each input batch atomically. On cap/build/sink error latch capture failure, record the first omitted boundary/reason and stop retaining; never evict old evidence or abort/retry the scientific tick. Snapshot cadence gaps censor inventory/settlement/institution continuity, but do not falsely censor independently complete event-receipt windows. Conversely, complete events do not repair missing private snapshots. Failed/aborted staging is released; recovered owner observations absent from staging provide no grounding witness.
7. Terminal goal finalization may occur after ordinary tick finalization. Capture relevant ledgers at the declared finalized boundary once; do not silently overwrite a previously published boundary. Capture does not claim durable subjective resume or completed-cell recapture. Missing initial prefix after a process restore is retained explicitly; starting a new sink never pretends that it witnessed boundary0.

### Interfaces and Requirement Evidence

`CivilizationCaptureOptions(enabled=False, cadence=1, max_boundaries=10000, max_rows=1000000, max_bytes=268435456)` is composition-only, never runner JSON/capability config. ## Task 5: Compose detached analytical and scoped historical layers

### Intent

Turn retained evidence into disclosed measurements and scoped claims, never objective terrain.

### Implementation Steps

1. In `experiments.civilization_publication`, normalize capture into analysis-owned inputs and call pure `analysis.civilization_overlays` calculators only after the run completes. Simulation/API/persistence must not import analysis. Consume only typed event receipts and their independently verified covered intervals from Task4. A flow window is complete only if its entire tick interval is covered; retained irrelevant-event counts are source-completeness evidence, not flow counts. Never assume a replay checkpoint's `history.events` contains the run prefix or pass raw event bodies to the publication model.
2. Implement the shared row contract above. Default flow/community window is trailing 32 ticks, `[max(0,B−32), B)`, fixed in policy `civilization-overlays.v1`; exact culture/technology inventories are at B. Publishers include the window and complete source coverage; no configurable hidden threshold in the UI.
3. Reuse cultural normalization and attribution contracts; if adopting `.cultural-evidence.json`/metrics, call `verify_cultural_pair` and match run/config/source/policy identities first. Never use a cell-wide endpoint metric as a per-boundary measurement. Raw native owner inventory is not proof of performability.
4. Feed candidate communities with living roster, accepted interaction edges and residence rows at that window; omit unavailable trust lane explicitly instead of inventing trust. Keep owner group beliefs separate from inferred communities. Use existing calculator identity, not client clustering.
5. Project each exact-boundary owner decay export with `institution_decay_rows_from_ledgers`. Native ledgers contain rolling historical samples: normalize cumulative exports by `(owner_id,local_pattern_id,observation_tick)` and attach `first_seen_boundary`. Identical repeated immutable sample content is one row; differing semantic sample content for the same key is a source conflict. Treat later retention/pruning flags and owner missing coverage as boundary-specific coverage metadata, not replacement historical samples. Preserve absolute source/span/structural witnesses and earlier captured samples after native eviction. For publication atB, include only samples first seen byB whose observation tick is <B (tickT cognition finalizes at boundaryT+1); initialB0 has no executed observation samples. Compute lifecycle with `compute_institutional_decay` over that qualified prefix and pass its result explicitly to `compute_institution_lineage(as_of_tick=B-1, lifecycle=...)` forB>0. Do not concatenate duplicate samples or let the lineage calculator's default EMERGING state substitute for lifecycle evidence. No future episode ends/retrospective pruning status may appear at earlierB. Attach only exact `InstitutionGroundingWitness` associations whose source exists at the evidence time; ungrounded institutions remain list/timeline rows. A demolished associated building does not itself prove institutional death.
6. Build history markers from complete supported changes: settlement candidate activation/deactivation, journey starts/arrivals, technology acquisitions and institution confirmed transitions. Each marker carries exact boundary/evidence class/source and safe reason. Missing spans produce coverage bands, not appearance/disappearance markers. Marker seek uses the committed post-event boundary.

### Interfaces and Requirement Evidence

New pure calculators return neutral detached rows; existing metric family catalog stays 136. This is a presentation read model, not a new comparative metric. Original Request — culture/technology/social groups/institutions; ARCHITECTURE — evidence boundaries; cultural metrics docs — explicit denominators; institution lifecycle's existing hysteresis remains authoritative for its classifications.

### Error Handling and Logging

Missing input yields layer-specific unavailable/partial status. Conflicting same identity/different content rejects publication, not last-write-wins. DEBUG layer/row/window/counts only; WARN identity/coverage conflicts with safe codes. No payload or content-identity logs.

## Task 6: Publish immutable history and expose opt-in CLI composition

### Intent

Provide an actual producer for the overlays while keeping HTTP a pure reader and research startup zero-install for browser users.

### Implementation Steps

1. Add filesystem adapters implementing distinct read/publication ports. Layout `<root>/<safe-run-id>/publications/<publication-id>/boundaries/<B>/manifest.json` plus scope/layer row shards; `catalogue/index.json` plus bounded catalogue-page shards; a single atomic run `state.json` reference selects the committed catalogue index. A boundary manifest lists typed scope/layer, coverage, shard path/digest, row count and stable first/last keys. Catalogue-page entries list boundary and its manifest digest. Catalogue index lists page key ranges/digests. Rows/shards contain no parent hash; hash shard bytes, then boundary manifests, then catalogue pages, then catalogue index, and finally write the commit reference. Every child carries stable run/world/publication/config/source/policy identity without a cyclic root digest. One publication covers a completed run's retained boundaries. Readers follow indexed committed refs only; never glob arbitrary files or repair orphan writes.
2. Enforce non-symlink paths, confined safe IDs, strict UTF-8/duplicate-key/nonfinite/unknown-key/depth/size validation before decoding. Use Task1 file/row caps. Seek through manifest key ranges, not by scanning the entire boundary. Reserve file/byte budget before reads: <=16 physical files/12MiB/request, <=2,000 decoded/scanned rows; stop before an unread shard and return the last scanned continuation, including an empty filtered page. Check on-disk size before reading and charge actual bytes; limit decomposed arrays too. Idempotent identical publication is accepted; differing data for the same identity is conflict. Use a single-writer lock, fsync immutable files/directories and atomically replace only the final reference. Interrupted publication stays invisible; storage/cumulative reservation accounting includes incomplete attempts so retries cannot evade quota.
3. Storage budgets: max10,000 boundary manifests, <=64MiB total encoded bytes per boundary including shards, <=1MiB/200rows per row/catalogue shard, <=64KiB per metadata index/manifest, cumulative256MiB/run across attempts/publications, 1,000,000 retained rows/receipts. Storage exhaustion writes a separate publication-status failure without reopening sealed scientific artifacts. An oversized row/layer is not silently omitted from a complete publication; report that layer's failure/partial coverage and never claim ready status for required unavailable output.
4. Add `research_runner.civilization_composition` installer/finalizer and typed outer `CivilizationExecutionHooks`/`CivilizationPublicationReceipt` in `experiments.civilization_capture`. Add installer/finalizer dependencies to `MatrixBatchDependencies` and optional durable `RunnerDependencyFactories`; thread them into `run_one_assignment` and its `SimulationRunner.from_config` call. Add separate civilization installer/finalizer fields to `GenerationalExecutionContext` and execute them in `execute_generational_assignment`; do not overload existing lineage callbacks or change their returned-session assumptions. CLI builds these hooks for both ordinary matrix cells and generational execution. Compose with existing cultural/lineage capture using separate sessions. Finalize only nonfailure scientific results; setup/publication errors produce a closed sidecar receipt, not a fake successful capture.
5. Add optional `compose.civilization.yaml`: API mounts `${PALIMPSEST_CIVILIZATION_HOST_ROOT:?}` at `/civilization:ro`, sets root `/civilization`, forwards `PALIMPSEST_CIVILIZATION_CURSOR_KEY`, `PALIMPSEST_API_INSPECTION_CREDENTIAL`, `PALIMPSEST_API_DEBUG_ENABLED` (defaultfalse), and `PALIMPSEST_API_DEBUG_CREDENTIAL` from operator environment.
