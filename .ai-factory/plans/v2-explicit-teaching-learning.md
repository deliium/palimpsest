2. Do not own a capability flag. Do not add a `V2CapabilityFlags` field. `multi_hop_testimony_tracking` stays unimplemented and still fails closed with `capability_unimplemented`. Off for this feature is `TeachingInteractionMode.DISABLED`, which does not change skill growth, probabilities, commands, memories, beliefs, or audits.
3. V1 regression gate stays green under flags-off, teaching mode `DISABLED`, skill mode `DISABLED`, and tracing-off. Catalog A–E and the reference scenario keep their current `exact_trajectory_hash` values. Experiments S and T are additive and must not be appended to `tests/unit/test_v1_regression_gate.py`.
4. `runner-config-v12` is the only new runner schema. It is emitted only when some agent's `TeachingInteractionMode` is `DETERMINISTIC`. `RUNNER_SCHEMA_VERSION` stays `runner-config-v4`. v12 cognition keys are the v11 key set plus `teaching_interaction_mode` and the locked weight keys below. Do not add a new event schema. `EVENT_SCHEMA_VERSION` stays replay-v5.
5. No scripted emergence. Acts are closed utterance predicates. There is no profession, role, culture, or teacher label, and no new `AgentCommand`.
6. No LLM → world shortcuts. A provider may only choose an act and a domain token the deterministic policy already allows. The claim band is computed from the owner's believed level. The provider never emits a level, a band, an `AgentCommand`, or a world mutation.
7. Experiments stay reproducible. Experiments S and T share seed, scenario, and stochastic identity across arms. Analysis runs after the run and is not fed back into cognition or into the engine.

Tracing on versus off must not change `exact_trajectory_hash` when teaching mode is off.

## Goal

Let agents teach and learn through four explicit interactions: demonstrate, explain, practice together, and request instruction. Transmission uses public utterances and public action outcomes. A learner's declarative advice, learned belief, and practiced capability are three different stores and may disagree. A teacher with a false competence belief can teach that false belief. The learner's objective skill does not become the teacher's hidden level.

## Design Decisions (locked)

- **Mode, not a flag.** `TeachingInteractionMode` is `DISABLED` or `DETERMINISTIC`, on `AgentCognitionSpec` and lockstep with `CognitionTeachingInteractionMode`. Default `DISABLED`. An agent with `DETERMINISTIC` teaching must have `SkillLearningMode.DETERMINISTIC` on that same agent. Fail closed with `teaching_requires_skill_learning` before bootstrap. Other agents in the run may leave both modes off.
- **Schema.** Non-disabled teaching is legal only on `runner-config-v12`. v12 requires some agent in `DETERMINISTIC` teaching. v11 and earlier reject the new keys. Every mode set that currently ends at v11 gains v12: skill learning, reputation, communication strategy, consolidation, reflection, prospective simulation, and counterfactual mode. Skill learning is accepted on `{v11, v12}`. The existing `schema_version == runner-config-v11` gates in `SimulationRunnerConfig` and `_encode_cognition` become membership in that set, so v12 still writes the skill keys and still runs `skill_rate_mismatch`. v12 then appends the teaching keys. A skill-only config still writes v11. A config that enables teaching writes v12. Default write stays `runner-config-v4`. `v1_regression_profile` still checks only capability flags and tracing. Export `RUNNER_SCHEMA_VERSION_V12` from `simulation/__init__.py` and cover it in `tests/unit/test_compatibility_matrix.py`.
- **Shared weights.** Every v12 agent carries the same teaching weight tuple. A mismatch fails closed with `teaching_weight_mismatch`. The run builds one `TeachingInteractionPolicy` from that tuple. Skill rates stay the v11 tuple and still fail with `skill_rate_mismatch`. `world/_teaching.py` may import `world._skills`. It must not import `agents`. `agents/cognition/teaching.py` must not import `world._skills`, `world._teaching`, or `world._state`.
- **Who participates.** Advice, belief uptake, and the extra practice deltas apply only when both the speaker and the recipient are in `teaching_entity_ids`, the entity ids whose agents are teaching `DETERMINISTIC`. The runner passes that frozenset into `WorldEngine`. A delivered utterance to a body outside the set still follows today's talk rules and adds nothing in the teaching fold.
- **Three stores.** Declarative advice is an owner-scoped record of a heard act. Learned belief is the existing `CompetenceSelfModel`. Practiced capability is the existing `ObjectiveSkillLedger`. Receiving an act never assigns the speaker's believed level, support mass, objective level, or relationship profile into the recipient.
- **Existing `instruct` stays put.** `_instruction_domain` and `instruction_rate * teacher_teaching_level` are unchanged. The new predicates are not `instruct`. Teaching mode off leaves `fold_skill_growth` and `update_competence` on their current paths. Passing no teaching policy into the engine skips the teaching fold.
- **Acts are one relation on Talk, Ask, or Tell.** Exactly one relation. Do not read utterance text. Any other shape is not a teaching act. Attach the teaching relation only after `render_communication_intent` returns, and only when that utterance's relation tuple is empty. Strategy `DISABLED` keeps today's command and then uses the same empty-relation attachment. If a relation is already present (`uncertain`, `decline`, reputation testimony, or any other predicate), skip the act and log `reason_code=relation_occupied`. Do not add a second relation.
  - `request_instruction` — object is one skill-domain token. No belief mass change. No objective domain delta.
  - `explain` — object is `{domain}:{band}` with band `low`, `uncertain`, or `high`. No objective domain delta.
  - `demonstrate` — object is one skill-domain token. Opens an offer. No objective delta on the talk tick.
  - `practice_together` — object is one skill-domain token. Opens an offer. No objective delta on the talk tick.
- **Claim band comes from the speaker's own believed level.** Thresholds use the quantized believed level: `< 0.34` is `low`, `< 0.67` is `uncertain`, otherwise `high`. The boundary values `0.34` and `0.67` belong to `uncertain` and `high`. A missing competence model does not emit a pedagogical relation. A false believed level produces that false band.
- **Belief uptake is the next prepare.** Same lag as competence: the observation for tick N carries tick N−1. `explain` with band `high` adds `belief_explain_rate * trust_factor` to support. Band `low` adds that mass to counter. Band `uncertain` adds neither. `CompetenceBelief` currently rejects `counter_mass != 0` with `reason_code=counter_mass`. Lift that constructor guard so a teaching update may store a positive counter. `update_competence` still writes counter `0` on its own channels. `trust_factor` is the first value from `project_trust_inputs` on the **owner's** directed profile toward the speaker. Missing profile yields `0.5`. Do not read the speaker's profile. Do not scale uptake by either agent's objective level. `request_instruction`, `demonstrate`, and `practice_together` store advice and do not change support or counter.
- **Advice record.** One row per heard act: occurrence id, source agent id, act, domain, band (`unspecified` when the act has no band), delivery tick. Map the `ObservedCommunication` speaker `EntityId` through the owner's identity bindings. Drop the row with `reason_code=unknown_speaker` when no binding exists. Cursor of occurrence ids caps at 32 per domain by dropping the oldest. An id already stored is skipped. Advice is not a semantic belief and does not emit `BeliefRevisionRequest`. `declarative_advice` rides `SubjectiveSnapshot`, `CognitiveLoopProposal`, and `CognitiveLoopResult` the same way `competence_model` does, so prepare sees the store from the previous tick.
- **Demonstrate opportunity.** On a later tick, the speaker's admitted successful public practice of that domain grants the addressed recipient an extra `demonstration_rate * (1 - recipient_start_level)` when all of these hold: both bodies are in `teaching_entity_ids`, the offer is still open, the practice tick is within `offer_window` of the delivery tick, the recipient is a living body at the action's start-of-tick `origin_location_id`, and effective visibility is `>= 0.5`. Read `recipient_start_level` from `self._skill_ledger` before `fold_skill_growth`. Add the teaching deltas onto the ledger that `fold_skill_growth` returns, so this tick's skill channels stay on that ledger. The extra delta does not multiply by the speaker's level. Public success is the existing success channel: successful untargeted search, targeted search, move, flee, or help. Misses do not grant the extra rate and do not consume the offer. One success consumes the matching offer. Other witnesses keep today's `observation_rate` only. The recipient also keeps today's `observation_rate` when they already qualify as a witness; the demonstration delta is additional.
- **Practice together.** On a later tick inside the window, if both the speaker and the recipient are in `teaching_entity_ids` and both have an admitted applied practice of that same domain in that same tick, and they share a start-of-tick location with effective visibility `>= 0.5`, each gains `practice_together_rate * (1 - own_start_level)` on that domain. `own_start_level` comes from `self._skill_ledger` before `fold_skill_growth`. The bonus is added onto the ledger that fold returns. Ordinary practice, success, and failure channels still apply. Stochastic failure still counts as the applied attempt. Rejected, conflicted, and deferred actions do not. The bonus is not multiplied by the other body's level.
- **Teacher skill and learner skill.** Teacher skill changes learning only by changing how often the demonstrated action succeeds under the existing resolver. Learner skill changes learning only as `(1 - own_start_level)` on the demonstration and joint-practice bonuses. Neither formula copies a hidden number from one body onto the other.
- **Communication success.** Only a delivered `Talked`, `Asked`, or `Told` opens an offer or stores advice. Visibility, co-location, and living-recipient rules stay the current talk rules. Teaching skill does not change talk delivery. This plan does not add a communication miss.
- **Request makes an explain more attractive.** In `_compare_pair`, when teaching mode is on and the owner's current observation contains an unmatched inbound `request_instruction` addressed to the owner, add `teaching_response_weight` (`0.25`) to the `COMMUNICATE` side's float term. A nonzero integer vote still wins. `_critical_vetoes` stays earlier and unchanged. The answering `explain` uses the owner's own band. `None` mode adds nothing.
- **Offers are refolded.** Do not add a teaching key to world-snapshot JSON and do not edit `src/simulation/journal.py`. Open offers are derived from committed events inside `offer_window`, the same way the skill ledger is refolded. A caller-supplied offer set that disagrees fails with `teaching_offer_mismatch`. Disabled runs skip the refold.
- **Checkpoint.** `declarative_advice` is an optional field on the in-memory `AgentRuntimeCheckpoint`, default `None`, validated the way `competence_model` is validated in `run_control.py`. `AgentRuntime` copies it in export and restore. The snapshot, proposal, and result fields from the advice-record rule round-trip with that checkpoint field. Do not bump a subjective schema and do not add an Alembic revision. Do not add the store to `subjective-v1`. Do not add a teaching key to the world snapshot.
- **Audits.** `TeachingAudit` rows are in-run and analysis-only on `SimulationRunnerResult`, default empty, not a field on `SimulationRunnerResultDocument`. Each row is agent id, store (`advice`, `belief`, or `objective`), act or domain token, band or quantized level, and tick. No utterance text.
- **LLM.** `TeachingInteractionPolicy.allow_provider` defaults to false. `allow_provider=True` calls `LLMProvider.generate` only through schema `teaching.selection.v1` and prompt package `llm/prompts/teaching/v1/`. The payload lists act and domain tokens the deterministic policy already permits. The schema returns one of those pairs. The band is then computed locally. Unknown tokens, missing provider, transport error, or schema failure keep the deterministic choice and set `fallback_used`. Import the `llm` facade from `agents.cognition.teaching_selection` only. `teaching.py` does not import the selection module. `CognitiveLoop` imports it only when `allow_provider` is true. Add `agents.cognition.teaching_selection -> llm` to the Pydantic forbidden-import contract's `ignore_imports` in `pyproject.toml`.
- **Quantize.** Levels use the existing local `round(value / 1e-6) * 1e-6` in each module that writes a level. Tests compare to that expression. They do not compare a sum to its raw literal when quantization can split them.
- **Fail closed.** Unknown act or domain tokens, a bad claim, non-finite weights, a non-positive `offer_window`, owner mismatch, and a listener who is not the recipient are dropped with stable reason codes or rejected at policy construction.

### Locked v12 weights

`TeachingInteractionPolicy`, version `teaching-interaction-v1`:

| Key | Default |
| --- | --- |
| `demonstration_rate` | `0.02` |
| `practice_together_rate` | `0.02` |
| `offer_window` | `8` |
| `belief_explain_rate` | `0.08` |
| `explain_low_below` | `0.34` |
| `explain_high_at` | `0.67` |
| `teaching_response_weight` | `0.25` |

`explain_low_below` and `explain_high_at` are unit-interval thresholds. `offer_window` is an integer in `1..64`. The other rates are nonnegative. `teaching_response_weight` is in `[0, 1]`.
