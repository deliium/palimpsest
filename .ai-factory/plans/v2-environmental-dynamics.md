## Compatibility contract

This plan extends the existing physical world. It must satisfy the Downstream V2 plan contract in `docs/architecture.md`.

1. V1 invariants intact. `WorldEngine` remains the only objective mutation authority for seasons, temperature bands, resource seasonality, depletion, regeneration, temporary shortages, and hazards. Cognition never receives `WorldState`, `EnvironmentalDynamicsSpec`, a future calendar, or another agent's observation.
2. Do not own a capability flag. Do not add a `V2CapabilityFlags` field. `multi_hop_testimony_tracking` stays unimplemented and still fails closed with `capability_unimplemented`. Off for this feature is `EnvironmentalDynamicsSpec is None`. That path does not change weather samples, regeneration, ambient temperature, commands, events, memories, beliefs, or audits.
3. V1 regression gate stays green under flags-off, dynamics off, and tracing-off. Catalog A–E and the reference scenario keep their current `exact_trajectory_hash` values. Do not append Experiment U to `tests/unit/test_v1_regression_gate.py`.
4. `runner-config-v14` is the only new runner schema. It is emitted only when the dynamics spec is not `None`. `RUNNER_SCHEMA_VERSION` stays `runner-config-v4`. v14 cognition keys are the v13 key set plus `environmental_dynamics`. Default event writes stay replay-v5. `EVENT_SCHEMA_REPLAY_V7` is accepted and is written only by a run whose spec is not `None`. `CURRENT_PHYSICAL_EVENT_SCHEMA_VERSION` and `EVENT_SCHEMA_VERSION` stay replay-v5. A production-only run still writes replay-v6. A run with dynamics writes replay-v7 whether or not the catalog is non-empty, and that schema accepts the replay-v6 production details. Do not mix schemas inside one run.
5. No scripted emergence. Season order, multipliers, shortage windows, and hazard rules are configuration. There is no culture, ritual, profession, or milestone that grants calendar knowledge. Agents do not receive the spec on `Observation`.
6. No LLM → world shortcuts. A provider never emits a season, a multiplier, a window, a hazard, or a world mutation.
7. Experiments stay reproducible. Dynamics are deterministic under the configured seed. Weather keeps the existing `weather` named stream. Season, bands, yields, shortages, and hazards draw no new stream. Experiment U and `environmental_dynamics@1` stay analysis-only and off the V1 regression gate.
8. Optional cognition tracing stays outside the objective fold. Do not insert a `ComponentKind` or an ordinal in `_STAGE_ORDER`. Do not add a `CognitionTraceStageKind`. Do not bump `COGNITION_TRACE_SUMMARY_SCHEMA` or add an Alembic revision. Tracing on versus off must not change `exact_trajectory_hash` when dynamics are off.

## Goal

Add a configurable environment the engine resolves and an observer can replay at any tick. Agents see only the current season, the current local temperature band, current local hazards, and current resource quantities. Recurring patterns are learned in the existing subjective causal model when `predictive_world_model` is enabled. The default-off path stays today's day/night cycle, Markov weather, and constant `regeneration_per_tick`.

Closed phenomena, all owned by `WorldEngine`:

- seasons
- temperature patterns
- resource seasonality
- resource depletion
- resource regeneration
- temporary shortages
- environmental hazards

Godot chooses colors and effects. Domain payloads and observer frames carry tokens, not drawing commands.

## Design Decisions (locked)

- **Absent spec is the default.** `WorldEngine` takes `EnvironmentalDynamicsSpec` as a keyword-only argument defaulting to `None`. `None` uses the current body of `apply_autonomous_physical_step` and `_resolve_system_effects`: same weather draws, same regeneration, same ambient formula `base + weather offset + phase offset`. No season, band, shortage, hazard, or node-crossing events. No new RNG purpose. Default bootstrap, V1 worlds, and `runner-config-v4` through `v13` pass neither. `PhysicalRules` stays `physical-v1`. Do not add season fields to `PhysicalRules` or to `canonical_physical_rules_bytes`.
- **Spec is not world state.** The calendar, multipliers, windows, and hazard rules live only on the spec object and on `runner-config-v14`. They are not fields of `WorldState` and they are not copied onto `Observation`. Unit tests may pass the same spec into the engine directly.
- **Public spec, private step.** Types and `example_environmental_dynamics()` live in `src/world/environment.py` and are re-exported from `world`. That module does not import `simulation`, `observer`, `api`, `agents`, or private `world._*` modules. The tick step stays in `src/world/_physical.py`. Sampling of weather stays in `simulation.engine`.
- **Season is a pure function of tick.** Closed `Season`: `spring`, `summer`, `autumn`, `winter`, in that order. `index = (tick // season_length_ticks) % 4`. Tick `0` is spring. A transition exists only when `tick > 0` and `tick % season_length_ticks == 0`. No stream is drawn. Example `season_length_ticks` is `48`. The scarcity scenario uses `4` so a two-year check stays short. `season_length_ticks` must be an integer `>= 1`.
- **Temperature pattern.** Ambient when the spec is set:

  `base_temperature + weather_offset + phase_offset + season_offset`

  Example offsets: spring `0.0`, summer `12.0`, autumn `0.0`, winter `-14.0`. Bands are closed and derived, not stored: `cold` when ambient `< 10.0`, `hot` when ambient `>= 30.0`, otherwise `mild`. A location base of `20.0` with clear day and summer is `34.0` (`hot`). The same base with night and winter is `4.0` (`cold`). A clear spring day is `22.0` (`mild`). Compare the band after this tick's weather update with the band implied by the pre-update weather and the previous season. Emit `TemperatureBandChanged` only when they differ. Do not store the band on `Location` or `WorldState`. Replay recomputes it from the folded weather, the tick, and the spec.
- **Existing weather stays.** The Markov matrix, `weather_period_ticks`, and purpose `weather` are unchanged. A paired run with the same seed and the same initial weather produces the same condition trace with the spec on or off. Season does not alter the transition row.
- **Resource seasonality and regeneration.** Effective regeneration is `round_physical(regeneration_per_tick * multiplier)`, then `0` when a matching shortage window contains the tick. Example multipliers: `ResourceKind.FOOD` is `0.0` in winter and `1.0` in the other three seasons. `WATER` and `MATERIAL` are `1.0` in every season. A missing pair fails closed with `yield_undefined`. A multiplier is finite and `>= 0`. When every matching multiplier is `1` and no window matches, the quantity trace matches the spec-off run. Regeneration still emits `ResourceRegenerated` for a quantity change that does not cross zero. Search extraction amount is not multiplied.
- **Depletion and recovery are witnesses.** Quantity still changes on the existing search, harvest, and regeneration events. `ResourceNodeDepleted` is emitted in the same tick when quantity goes from `> 0` to `0`. `ResourceNodeRecovered` is emitted when it goes from `0` to `> 0`. Each carries `resource_id` and `resulting_quantity`. Replay fold checks that the folded quantity equals `resulting_quantity` and does not apply a second delta. `resulting_quantity` is `0` on depletion and `> 0` on recovery.
- **Temporary shortages.** `ShortageWindow` has `resource_kind`, `start_tick`, and `duration_ticks` (`>= 1`). The window covers `start_tick <= tick < start_tick + duration_ticks`. It suppresses regeneration for that kind. It does not zero stock by itself and it does not change maximum quantity. Overlapping windows are legal. The window list is ordered by `(start_tick, resource_kind.value)` and duplicate identical triples fail with `duplicate_shortage_window`. Windows are not on `Observation`.
- **Hazards.** Closed kinds: `cold_snap`, `heat`. A rule names `season`, `weather`, `band`, `duration_ticks` (`>= 1`), and `exposure_extra` (`>= 0`). Example rules: `cold_snap` when winter, `storm`, and `cold`, duration `6`, extra `5.0`; `heat` when summer, `clear`, and `hot`, duration `6`, extra `5.0`. On a tick whose location matches, start the hazard if that kind is not already active there. The condition does not have to remain true. A hazard is active while `start_tick <= tick < start_tick + duration_ticks`. `remaining_ticks` at tick T is `duration_ticks - (T - start_tick)`. The start event records `duration_ticks` and that remaining value. The ended event is emitted on the closing tick, which is `start_tick + duration_ticks - 1`, with `remaining_ticks` 0, and the hazard is absent from state after that tick. Empty ticks emit no countdown event. Replay recomputes remaining from `start_tick`, `duration_ticks`, and the requested tick. While the hazard is active, add `exposure_extra` to exposure damage for living bodies at that location. If `PhysicalRules.exposure_damage == 0`, the added extra is `0`, so `non_lethal_physical_rules` stays non-lethal. Death cause remains `DeathCause.EXPOSURE`. Do not add a death-cause enum member. One active hazard per `(location_id, kind)`.
- **Hazard state is the only new world field.** `WorldState` gains `active_hazards`, default empty. Each record has `location_id`, `kind`, `start_tick`, and `duration_ticks`. `remaining_ticks` is derived. `rebuild_world_state` copies the collection. Existing constructors that omit it keep an empty collection. `PERSISTENCE_CODEC_VERSION` stays `v2`. A dynamics-off checkpoint keeps today's key set and rejects `active_hazards`. A dynamics-on checkpoint writes codec `v4` and requires `active_hazards` plus the three v3 production keys (`structures`, `production_jobs`, `tool_marks`), which are empty when the catalog is empty. v3 decode rejects `active_hazards`. `PROJECTOR_VERSION` stays `v2`.
- **Events.** Add details `SeasonChanged`, `TemperatureBandChanged`, `ResourceNodeDepleted`, `ResourceNodeRecovered`, `EnvironmentalHazardStarted`, and `EnvironmentalHazardEnded`. Each is legal only on replay-v7 (`invalid_event_schema_version` below that). Production details stay legal on replay-v6 and are also legal on replay-v7. `SeasonChanged` carries the new `Season`. One season event is emitted per transition. Its system cause uses the lowest location id. `TemperatureBandChanged` carries `location_id` and the new band. Node witnesses carry `resource_id`. Hazard start carries `location_id`, `kind`, `duration_ticks`, and `remaining_ticks`. Hazard ended carries `location_id`, `kind`, and `remaining_ticks` 0. Domain payloads have no fields named `pixels`, `sprite`, `animation`, `color`, `dx`, `dy`, `screen_x`, or `screen_y`. Append `SystemEffectFamily` members `SEASON`, `TEMPERATURE_BAND`, `HAZARD`, and `RESOURCE_NODE` at the end of the enum. Do not rename `WEATHER`, `REGENERATION`, `COMBINED_NEEDS`, `EXPOSURE`, or `PRODUCTION`.
- **Step order inside the autonomous close, spec on only.** Season witness, then the existing weather update, then band witnesses, then shortage-gated seasonal regeneration and node witnesses, then hazard start, then the existing needs and exposure (with extra), then the ended witness on a closing tick. Spec off skips every new stage and keeps the current order. Search, drink, and harvest emit node witnesses in their own resolution when the spec is set and quantity crosses zero.
- **Agents see the present only.** When the spec is `None`, `Observation` serialization omits `season`, `temperature_band`, and `hazard_kinds` (optional keys, same discipline as `structures`). When the spec is set, perception adds the current season, the current band at the observer's location, and the current hazard kinds at that location. Local resources stay current quantities under `CONTENT_VISIBILITY_THRESHOLD` (`0.5`). There is no field for the next season, `season_length_ticks`, multipliers, windows, rules, or remaining ticks. A test constructs an observation and asserts those names are absent from its serialized mapping.
- **Causal discovery stays subjective.** When `predictive_world_model` is off, add no atoms, no successor table, and no command bias. When it is on and `observation.season` is `None`, behavior matches today, so Experiment I stays hash-stable. Append `CausalSlot.SEASON`, `CausalSlot.TEMPERATURE_BAND`, and `CausalSlot.HAZARD` after `CONCEPT`. `_SLOT_ORDER` follows declaration order, so existing slots keep their indexes. When the season is present, copy those three slots from that observation only. `SeasonSuccessorTable` is owner-scoped on the causal model. It increments only when the owner's stored previous season token differs from the current observation season. Prospective search scoring may replace `SEASON` with that unique successor only when its count is `>= 1` and exactly one successor is recorded. Two successors, or a count of `0`, leave the atom on the current season. The table is not initialized from the spec. Cognition must not import `world.environment`.
- **Long-horizon usefulness is a scenario, not a new planner.** `scarcity_scenario_dynamics()` uses `season_length_ticks = 4`, food regeneration `1.0`, food maximum `1.0`, and the winter food multiplier `0.0`. `seasonal_scarcity_scenario()` is one location, one food node, one agent, a seeded `GoalHorizon.LONG_TERM` goal with `GoalOutcomeKind.PRESERVE_LIFE`, and two arms that share the seed. Arm `learned` enables `predictive_world_model`. Arm `naive` leaves it off. Do not add a planner stage. The unit proof feeds the learned arm a winter `search_failure` observation and then an autumn observation, and asserts the search bias is lower than the naive model. It also asserts the same seed run twice folds identical season boundaries and quantities, and that a second seed changes weather but not season boundaries.
- **Runner schema.** v14 is accepted only when the spec is not `None`. v13 and earlier reject `environmental_dynamics`. Production is accepted on v13 or v14. A production-only config still writes v13. A dynamics config writes v14 and may carry an empty or non-empty catalog. Skill learning is accepted on `{v11, v12, v13, v14}`. Teaching is accepted on `{v12, v13, v14}`. `v1_regression_profile` still checks flags and tracing only.
- **Observer protocol stays v1.** Do not change `OBSERVER_PROTOCOL_VERSION`. Keep every current semantic type. Add `SEASON_CHANGED`, `TEMPERATURE_BAND_CHANGED`, `RESOURCE_NODE_DEPLETED`, `RESOURCE_NODE_RECOVERED`, `ENVIRONMENTAL_HAZARD_STARTED`, and `ENVIRONMENTAL_HAZARD_ENDED`. `WEATHER_CHANGED` already exists. `len(SEMANTIC_EVENT_TYPES)` becomes `32`. Frames gain optional `season`, per-location `temperature_bands`, and per-location `hazards`. Resource `quantity` is already projected; depleted is `quantity == 0` and is not a second source of truth. `public_mapping` includes the new ids only when set. Do not switch observer responses to `exclude_none`.
- **Write pair.** Spec set selects replay-v7 and codec `v4`. Production without a spec selects replay-v6 and codec `v3`. Otherwise the write stays replay-v5 and codec `v2`. `schema_projector_compatible` accepts schema 7 with projector `v2`. `RunCreateRequest` accepts the v7/v4 pair the same way it accepts the v6/v3 pair.
- **Replay reconstructs the projection.** `ReplayRequest`, `project_events`, and `project_event_prefix` take `environmental_dynamics` the same way they take `production_catalog`. `project_event_prefix` at an arbitrary tick, then `project_frame`, must equal the live engine scene at that tick for season, weather condition, temperature band, resource quantity, and active hazard kind. Remaining ticks use the hazard formula at the requested tick. The Godot client already replaces its world from `state_tick` via `world_replaced`. It must paint those tokens from the snapshot through `theme_catalog.gd`. It must not read a color or sprite from the server.

### Locked numbers

- Example season length `48`. Scenario season length `4`.
- Season offsets: spring `0`, summer `12`, autumn `0`, winter `-14`.
- Bands: cold below `10`, hot at or above `30`, else mild.
- Food winter yield `0`, every other example yield `1`.
- Hazard duration `6`, hazard extra `5.0`, suppressed when `exposure_damage` is `0`.
- Reference location base `20.0` is the band example, not a change to the reference scenario.
- No new entity id allocator. Hazards are `(location_id, kind)`, not entities.

## Non-Goals

- Replacing day/night or the Markov weather chain
- Owning `multi_hop_testimony_tracking` or adding a `V2CapabilityFlags` field
- Putting Experiment U on the V1 regression gate
- Sending future seasons, yields, windows, or hazard rules to an agent
- A new cognitive stage, a new goal kind, or a new `DeathCause`
- Sprite, particle, color, or coordinate commands on domain events or observer frames
- An Alembic revision or a cognition-trace stage
- Changing the reference scenario or catalog A–E trajectories
