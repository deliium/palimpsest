# Civilization paged reads exceed the per-request file budget

**Date:** 2026-11-01 23:40
**Files:** src/persistence/civilization_filesystem.py, tests/unit/test_civilization_filesystem.py
**Severity:** high

## Problem

`tests/benchmarks/test_civilization_playback.py::test_dense_civilization_render_pack_pages_are_bounded`
failed with `CivilizationError("civilization_read_budget")`. The benchmark publishes
2,000 rows (ten 200-row shards) and pages through them with a 200-row limit. Page 9
needed ten row shards plus seven catalogue/state files — 17 physical files — while
`CivilizationReadBudget` allows 16 per request. Page 10 then failed outright.

Reproduced locally in about 5 s; no `civilization*` source changed between the V4-04
base and this fix, so the failure looked pre-existing at first glance.

## Root Cause

Commit `e2fb628` (paged historical indexes) added `row-bounds.json` and an
in-shard skip, and commit `8f050a9` replaced index keys that embedded row keys
with `scope_tag|boundary|shard_ordinal` keys (to fix duplicate byte-split index
entries). The row-key skip inside the reader was replaced by decoding the first
and last row of every candidate shard — but only *after* `_read_budgeted` had
already charged the file.

As a result, page *k* re-read all *k-1* earlier shards to discover they were
exhausted. The per-request allowance was consumed by replay, so the last pages of
any publication with roughly ten or more shards hit the 16-file cap. The reader
already had the publisher-written `row-bounds.json` available but never consulted
it for skipping.

## Solution

- Added `FilesystemCivilizationReader._row_bounds`, which loads the boundary's
  `row-bounds.json` through the normal read budget and returns
  `{full shard path: (first_row_key, last_row_key)}`.
- Before reading a candidate shard, skip it when its published last row key is at
  or before `after_key`. Shards are written in globally sorted row-key order, so
  the skip cannot drop a row that belongs on the page.
- The bounds file is advisory publisher metadata: absent files and oversized files
  fall back to the previous `_read_budgeted` path (warning logged, no behavior
  change). Row values are still digest-verified when a shard is read.
- Bounds are loaded only when `after_key` is present, so the first page pays
  nothing extra.
- Added
  `test_many_shard_pages_stay_within_the_per_request_file_budget` (2,000 rows,
  ten shards) asserting `budget.physical_files <= 12` on every page. It fails
  before this change at the file-count assertion and passes after.

## Prevention

- When a paged reader has to honor a global key order across shards, skip
  exhausted shards from persisted bounds instead of decoding them inside the
  request.
- A per-request physical-file budget must be asserted per page in a test whose
  shard count exceeds the budget headroom. The earlier 450-row test (three shards)
  could never reach the cap.
- The scale benchmark lane is the only lane that exercised this density; keep it
  in the qualification receipt rather than treating it as optional.
