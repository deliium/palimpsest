# V4-11 verification blockers: researcher-only recollection, treaty metrics, UI, and store coverage

**Date:** 2026-11-05 18:42
**Files:** src/agents/cognition/diplomacy.py, src/agents/cognition/__init__.py, src/analysis/diplomacy_contract.py, src/analysis/diplomacy_detection.py, src/analysis/diplomacy_identity.py, src/analysis/diplomacy_layers.py, src/analysis/diplomacy_metrics.py, src/analysis/diplomacy_rows.py, src/analysis/diplomacy_alignment.py, src/analysis/specifications.py, src/simulation/diplomacy_models.py, src/simulation/diplomacy_paging.py, src/experiments/diplomacy_harvest.py, src/experiments/diplomacy_publication.py, clients/research-ui/src/views/DiplomacyPanel.svelte, clients/research-ui/src/views/DiplomacyPanel.test.ts, tests/unit/test_diplomacy_treaty_*.py, tests/architecture/test_treaty_boundaries.py
**Severity:** high

## Problem

`$aif-verify` for `v4-11-treaties` found blocking gaps despite all plan checkboxes being marked complete:

- cognition compared a recollection's claimed digest with the retained version digest and appended a treaty recollection conflict;
- treaty analysis rows never carried treaty counts, and candidate detection ignored treaty evidence;
- `apparently_accepted_count` counted two declarations as acceptance for any party count;
- the Research UI imported `getDiplomacyTreaties` but never called it, so the Treaties section was always empty;
- the required v2 store test file was absent;
- the in-process E2E used a computed institutional-memory token instead of a real ledger entry;
- withdrawal terminated only at zero non-owner participants rather than the planned threshold;
- capacity pruning did not protect treaty participants/declarers;
- v2 snapshots did not validate owner/party references or closed status/basis labels;
- treaty pages sorted by ID rather than tick;
- treaty metric provenance was omitted for zero-treaty runs;
- the boundary suite covered only a subset of the named invariants.

## Root Cause

The implementation was written against the high-level task checkboxes and the focused tests, while several detailed phase contracts were not encoded in tests:

- The "misremember is researcher-only" rule was implemented in both analysis and cognition, with the cognition conflict treated as a retained belief rather than as a forbidden truth comparison.
- Analysis row fields were added without a producer, and candidate detection was left relation/contact-only.
- Metric acceptance reused the earlier two-party test shape, so a `>= 2` shortcut passed all tests.
- The UI test fixtures contained treaty data but never asserted treaty rendering, hiding a missing fetch.
- Store behavior was exercised only by V4-10 tests; no v2 coexistence test existed.
- The E2E helper computed an institutional-memory ID without constructing the source ledger.
- Several capacity/snapshot/paging checks were unreachable or unasserted, so the shortcuts survived.

## Solution

- Removed the cognition-side claimed/retained digest comparison. Subject-kind recollection conflicts remain retained; digest alignment stays in `analysis.diplomacy_alignment`.
- Added treaty evidence to candidate detection and populated `DiplomacyAnalysis` treaty/version/accepted/lineage counts.
- Added pure `treaty_version_accepted` and `treaty_version_status_label` helpers; metrics and summaries now require every version participant to accept.
- Populated `treaty_status_counts` in the subjective layer and expanded forbidden result fields with truth/verification/legitimacy/binding/enforcement names.
- Fetched the treaty page in `DiplomacyPanel.svelte` and added a treaty-row/detail UI test.
- Added `tests/unit/test_diplomacy_treaty_store.py` for v2 round-trip, mixed v1/v2 roots, idempotence, quotas, and failure isolation.
- Constructed a real `InstitutionalMemoryLedger` entry in the E2E and asserted its retention.
- Changed withdrawal termination to the planned fewer-than-two-non-owner threshold and added a withdrawal test.
- Protected treaty participants/declarers during party pruning and used `treaty_capacity_reached` for participant/provision caps.
- Added v2 owner/party cross-reference validation and closed status/basis/change/act/kind checks.
- Sorted treaty and lineage pages by tick then ID.
- Emitted all four treaty metric families whenever diplomacy rows exist.
- Expanded the treaty boundary suite with command-path, analysis-detachment, identity-mutation, frame-bound, store-schema, and `/v2`/observer checks.

## Prevention

- Encode every detailed phase acceptance check as a test; a green focused suite is not evidence for unasserted steps.
- Keep "researcher-only" classifications out of cognition even when the field is named `conflict` rather than `truth`.
- For acceptance metrics, compare against the retained participant set, not a fixed minimum.
- UI fixtures must assert rendered feature rows, not only provide mock endpoints.
- Add mixed-schema store tests when a new snapshot version is introduced.
- E2E tests must construct real source objects, not just their deterministic IDs.
- Keep boundary suites aligned with the named anti-pattern list; exact-name AST checks catch symbol drift but not semantic shortcuts.
