# Distinction proof compared a class object with the scenario

**Date:** 2026-09-26 22:19
**Files:** tests/unit/test_counterfactual_distinction.py
**Severity:** low

## Problem

The five-way distinction test treated `SemanticBelief` as a type marker instead of building a belief whose predicate is not `counterfactual_alternative`. It also compared the scenario with `ObservedOccurrence` and never asserted it was not an `Observation`.

## Root Cause

The proof was written against class objects because constructing a full semantic belief needs several belief-state fields. That check still passes if a scenario were somehow the class, and it never shows an ordinary stored claim next to the counterfactual revision request.

## Solution

Build an ordinary belief with predicate `at_location` through the existing goal-manager fixture. Assert that belief is a `SemanticBelief`, that its predicate is not `counterfactual_alternative`, and that the scenario is neither that class nor the loop input's `Observation`. The counterfactual revision request stays a separate object that cites the real memory id.

## Prevention

When a plan says "build one of each", instantiate the ordinary record with a non-matching predicate and assert both the class and the live observation type. A class-object comparison is not that proof.
