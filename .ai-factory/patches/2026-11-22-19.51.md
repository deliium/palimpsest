# V4-34 disease mechanics failed its own verification gates

**Date:** 2026-11-22 19:51
**Files:** src/simulation/bootstrap.py, src/simulation/runner.py, src/simulation/engine.py, src/simulation/persistence.py, src/simulation/replay.py, src/simulation/serialization.py, src/simulation/disease_checkpoint.py, src/world/_disease.py, src/api/observer_service.py, docs/configuration.md, docs/architecture.md, .ai-factory/DESCRIPTION.md, .ai-factory/ARCHITECTURE.md, tests/unit/*, tests/architecture/*, tests/simulation_helpers.py
**Severity:** high

## Problem

`$aif-verify` on `v4-34-disease-mechanics` reported a failing gate even though all
nine plan tasks were checked:

- `lint-imports`: `simulation.runner -> world._disease` (private world authority).
- 5 architecture tests failed on the same import.
- `ruff check src tests`: 27 errors in the new disease seam.
- `mypy src tests`: 23 errors (object-typed disease rows, untyped helpers,
  `SnapshotExtensions` missing `disease_mechanics`).
- Full `tests/unit tests/architecture`: 60 failed, 12 947 passed — mostly stale
  ownership/version/death-cause documentation pins, plus a real schema-24 bug.
- `.ai-factory/DESCRIPTION.md` had no V4-34 entry and stale ownership counts.

## Root Cause

1. **Import placement drift.** Founder latent rows were composed in
   `simulation.runner` instead of `simulation.bootstrap`, so a legal
   simulation-to-private-world edge was added where the contract permits only
   `simulation.engine`/`simulation.bootstrap`.
2. **Typing was deferred behind `object`.** Disease rows crossed bootstrap,
   engine, journal, service, replay, and serialization as `object`, pushing type
   errors into call sites and hiding that `SnapshotExtensions` and
   `WorldSnapshot` had no typed disease key.
3. **Compat set omission.** `schema_projector_compatible()` was never extended
   for `EVENT_SCHEMA_REPLAY_V24`, so no schema-24 checkpoint could be hashed or
   restored. Unit tests only folded events; the integration test that writes
   checkpoints is env-gated, so the omission passed.
4. **Pin tests were treated as documentation, not compile-time contracts.**
   Historical guards that assert "`v22` is not accepted", "`epidemics` is
   unowned", or "the `DeathCause` enum has four values" were not updated with
   the planned pin changes, so the suite no longer described the product.
5. **Documentation checkpoint was marked done without the DESCRIPTION update**,
   leaving contradictory ownership text in three files.

## Solution

- Moved founder-row composition into `simulation.bootstrap.disease_bootstrap_state`
  and made `simulation.runner` call it, restoring the private-import allowlist.
- Typed `disease_state` through `WorldBootstrap`, `WorldSnapshot`,
  `ReplayRequest`, `SnapshotExtensions`, engine helpers, journal encoding, replay
  paging, serialization helpers, and the observer visible list. Removed two
  stale `type: ignore` comments.
- Added `EVENT_SCHEMA_REPLAY_V24` to `schema_projector_compatible`.
- Re-pointed stale guards to the next unclaimed version (v23 codec, v59 runner),
  updated owned/unowned flag sets and counts to 10/2, added `disease` to the
  `DeathCause` and `SystemEffectFamily` expectations, and preserved historical
  doc pins while updating current baselines to V4-34.
- Added a unit regression test proving restore rejects a mismatched policy
  digest, reads without a policy, and binds a verified one.
- Updated `.ai-factory/DESCRIPTION.md`, `.ai-factory/ARCHITECTURE.md`
  (stale unowned line plus a V4-34 seam section), and `docs/architecture.md`
  deferred-scope wording.

## Prevention

- Plan checkboxes must not be marked complete until the plan's own verification
  commands are green; run `lint-imports` before closing any plan that touches
  `world._*`.
- Never add a replay schema to the accepted set without adding it to
  `schema_projector_compatible`, and cover hashing/restoring a minimal checkpoint
  in a fast unit test (not only the integration lane).
- When a plan changes global pins, update every guard in the same commit or
  replace the guard with the next open slot; a red guard is a specification
  mismatch, not noise.
- Type new domain rows at the boundary where they are created; `object` in a
  dataclass annotation is a deferred failure.
- Treat DESCRIPTION/ARCHITECTURE/ROADMAP ownership lines as part of the
  definition of done, not optional prose.
