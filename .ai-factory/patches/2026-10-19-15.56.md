# Unreachable institution named_custom path and missing BF arbiter evidence

**Date:** 2026-10-19 15:56
**Files:** src/agents/cognition/institution_concepts.py, tests/unit/test_institution_concepts_loop.py, tests/unit/test_institution_composition.py, tests/unit/test_experiment_bf.py
**Severity:** medium

## Problem

Verification of the V3-29 institution-emergence plan found that the plan's
acceptance evidence was incomplete:

- `InstitutionConceptualization.NAMED_CUSTOM` could be constructed directly but
  was unreachable through the update/transmission path. No custom predicate was
  ever emitted or observed, so "named_custom is reachable without
  semantic_naming_mode" was false in practice.
- The Experiment BF test supplied a synthetic "restored" concept-id map to the
  arbiter instead of driving a real checkpoint export/import round trip.
- The BF baseline arm asserted `runner-config-v4` but not a pinned pre-plan
  trajectory hash.
- Institution harvester tests did not cover snapshot-equivalent input
  projection or empty/missing channel behavior.

## Root Cause

The institution-concept transmission implementation only recognized the
`institution_pattern` predicate. Convention cognition already models a separate
self-contained `custom` predicate that marks an existing belief as
`NAMED_CUSTOM`; the institution analogue was omitted, leaving the enum branch
dead code. The BF arbiter tests were written around structural counts and
assumed restore fidelity instead of proving it, and the golden hash was never
pinned.

## Solution

- Added `_CUSTOM_PREDICATE = "custom"` and a second relation to
  `institution_communicate_utterance()` when the chosen recognized concept is
  `NAMED_CUSTOM`. The relation encodes the sender group key and opaque label
  token; the receiver re-derives its own group key from the pattern relation and
  attaches the label through `_apply_custom_label()` with COMMUNICATED evidence.
  No sender ledger rows are copied and no semantic-naming mode is consulted.
- Added `test_custom_label_is_reachable_without_semantic_naming_mode`, which
  drives a real Talk stamp plus receiver observation and asserts an independent
  receiver concept with the custom label.
- Added a real `export_runtime_checkpoint()` / `apply_runtime_checkpoint()`
  round trip to `test_bf_checkpoint_round_trip_preserves_owner_ledgers`,
  asserting before/after ledger parity and per-owner non-empty concepts.
- Pinned the coordinator-materialized `bf-baseline` exact trajectory hash for
  `max_ticks=4` in `test_bf_baseline_matches_pre_plan_golden_hash`.
- Added snapshot-equivalent projection and empty-channel assertions to
  `tests/unit/test_institution_composition.py`.

## Prevention

- Enum branches that represent externally reachable states need an explicit
  end-to-end test through the public update path, not only a constructor test.
- When a plan requires checkpoint round-trip evidence, use the real
  export/import API; a hand-built comparison map proves nothing about restore
  fidelity.
- Any "pre-plan golden hash" acceptance criterion must pin a concrete hash from
  the coordinator-materialized arm (the hash includes `run_id`).
- Harvesters should be tested with both detached snapshot-equivalent inputs and
  empty channel inputs.
