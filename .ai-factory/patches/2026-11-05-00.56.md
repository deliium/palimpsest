# V4-10 verification blockers: strict typing, real E2E, and documentation sweep

**Date:** 2026-11-05 00:56
**Files:** src/simulation/diplomacy_codec.py, src/agents/cognition/diplomacy.py, src/simulation/runner_models.py, src/api/routes/diplomacy.py, src/analysis/diplomacy_rows.py, src/experiments/diplomacy_publication.py, src/simulation/diplomacy_paging.py, tests/unit/test_diplomacy_*.py, tests/architecture/test_diplomacy_boundaries.py, tests/unit/test_dispute_docs.py, tests/unit/test_formal_rule_docs.py, .ai-factory/DESCRIPTION.md, .ai-factory/ARCHITECTURE.md, docs/disputes.md, docs/v4-architecture.md, docs/evidence-testimony.md
**Severity:** high

## Problem

`$aif-verify` for `v4-10-diplomacy` found four blocking gaps:

- `uv run mypy src tests` failed with seven strict-mode errors in V4-10
  modules and tests, even though the plan receipt recorded the lane as passed.
- The in-process E2E used synthetic `SimpleNamespace` ledgers and direct
  `apply_diplomacy_update` calls instead of a real admission/speech/recognition
  path, and read only three of six routes.
- The physical-distinction suite used source-string scans instead of real
  `WorldEngine` admission, and the boundary suite was missing seven named cases.
- Current documentation still said `diplomacy` was unowned in
  `.ai-factory/DESCRIPTION.md`, `.ai-factory/ARCHITECTURE.md`,
  `docs/disputes.md`, and `docs/v4-architecture.md`.

## Root Cause

- The V4-10 code used `object`-typed parameters and `getattr` results without
  narrowing, and `decode` reached `__dataclass_fields__` through a `type` value.
  The receipt was written from an earlier/partial run rather than re-run after
  the final commits.
- The E2E was written to exercise the composer and routes quickly, which
  skipped real contact, speech serialization, and representation recognition.
- The boundary suite covered the highest-risk claims but not every case named by
  the phase specification; the physical test substituted a static scan for an
  admission proof.
- The docs sweep updated current catalog pins but missed later ownership blocks,
  and the parity test asserted only presence of new phrases, never absence of
  stale ones.

## Solution

- Narrowed the `object`-typed values (`getattr`, `cast`, `dataclass_fields`) so
  strict mypy passes across 2,050 files.
- Rebuilt the E2E to produce a real `ContactRecorded` through `WorldEngine`
  (cross-region journey, `cultural_contact_active=True`), attach a real `dip_v1`
  frame to a `Talk` via `diplomacy_communicate_utterance`, parse it back, build a
  real representation ledger to `recognized`, recall the envoy, publish, and read
  all six routes. It also asserts agreement and trade lane builders.
- Rewrote the physical-distinction suite around real `WorldEngine` admission for
  possible and impossible commands and added the seven missing boundary cases.
- Swept every current four-owned/eight-unowned statement and the
  `diplomacy` context status, and added a negative docs parity test.
- Fixed two real composer defects the new E2E exposed: envoy terminations now
  publish against the reminted envoy id (and harvest keeps only hashed envoy
  targets), and relation detail now includes envoy-target terminations.

## Prevention

- Re-run static gates after the final test/documentation commit, never from an
  intermediate state.
- Prefer real engine objects and admission in end-to-end tests; a passing
  synthetic test can hide reference-mapping defects.
- Keep a negative parity assertion for every "X is unowned/deferred" phrase
  when ownership changes.
- When publishing reminted ids, map every referencing row (terminations,
  conflicts, declarations) through the same id table.
