# Real completed-run assembly double-harvested organization rows

**Date:** 2026-11-04 21:15
**Files:** `src/analysis/organizations.py`, `tests/integration/test_delegation_representation_e2e.py`, `tests/unit/test_delegation_representation_publication.py`, `tests/unit/test_delegation_representation_revocation.py`, `tests/unit/test_organization_harvest.py`
**Severity:** medium

## Problem

A real completed-run assembly with the owned `organizations` capability active
failed with `organization_row_owner_mismatch`. `experiments.collectors` already
harvested `organization_concept_ledgers` into `OrganizationHarvestRows` before
calling `analysis.metric_service`, and the metric service harvested the field a
second time. The second pass treated each harvest row as an exported ledger and
read a missing `owner_id`, producing a `None` owner.

The V4-09 end-to-end scenario also under-covered its committed acceptance
criteria: it did not exercise delegation/`duplicate_mandate`, settlement
principal resolution, unauthorized revocation, representation metric emission
through the real collector, cursor invalidation after a digest change, or
admission independence.

## Root Cause

`harvest_organization_rows` accepted only raw ledgers. Sibling harvesters for
organization operations and formal rules accept their own normalized rows, so
the two-stage collector → metric-service call was safe for those families but
not for organization concepts. Existing unit tests called the metric service
directly with raw ledgers, so the double-harvest path was never exercised until
the V4-09 collector assertion ran a real completed-run assembly.

## Solution

`harvest_organization_rows` now detects an already-normalized sequence and
returns it through the same duplicate-owner check and deterministic ordering.
Raw ledgers still take the existing projection path. The V4-09 end-to-end test
was extended to cover principal delegation with coexisting recognized mandates,
unauthorized revocation, settlement anchors, real metric-document assembly via
`assemble_arm_metric_bundle`/`collect_catalog_metrics`, digest-bound cursor
rejection, and physical admission independence. Focused store tests now cover
conflicting duplicates, concurrent publisher serialization, and the cumulative
byte quota, and the revocation suite covers the fourth conflict kind.

## Prevention

- Normalization helpers that a collector may feed into the metric service must
  accept their own output or the collector must pass raw values; pick one
  contract per family and test the real two-stage path.
- Acceptance criteria that name concrete scenario steps need one integration
  test that asserts each step, not just unit coverage of the underlying helper.
- Keep append-only catalog and snapshot sibling suites in the rerun set after
  touching shared harvest or metric assembly code.
