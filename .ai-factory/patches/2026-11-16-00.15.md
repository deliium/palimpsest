# Economic-cascade verification test-gap closure

**Date:** 2026-11-16 00:15
**Files:** tests/unit/test_economic_cascades_routes.py, tests/unit/test_economic_cascades_end_to_end.py, tests/unit/test_economic_cascades_collector.py, tests/unit/test_economic_cascades_runner_e2e.py, .ai-factory/plans/v4-26-economic-cascades/index.md
**Severity:** low

## Problem

Post-implementation verification passed every executable gate but found three
test-depth gaps against the V4-26 plan:

- The seven routes were tested through a hand-assembled FastAPI app, so the
  production `_attach_economic_cascades_reader` wiring and its dual-gate
  behavior were never exercised.
- No route test asserted the documented `410
  economic_cascades_cursor_expired` path, even though the cursor codec TTL was
  unit-tested.
- The in-process E2E used one 32-tick window, so cross-window paging and a
  two-window analysis were not proven; the collector test stubbed the real
  builder and never exercised collector → real builder → metric documents.

## Root Cause

The tests followed the older V4-24/V4-25 pattern of assigning
`app.state.economic_cascades_reader` directly and building a single-window
fixture. That kept the tests fast but bypassed the composition-root attachment
and the multi-window contract that the V4-26 phase files explicitly required.

## Solution

- Added `test_app_factory_attaches_the_dual_gated_reader`, which calls
  `create_app` with both settings and asserts a real summary read, then calls it
  with only the root setting and asserts reader/codec are `None`.
- Added `test_expired_cursor_is_gone`, which mints a cursor with an injected
  past clock and asserts the route maps it to `410` with
  `economic_cascades_cursor_expired`.
- Extended the in-process E2E to a two-window run (two resource nodes, zeroed
  metabolism/exposure so agents survive the longer horizon) and to page
  `disruptions` across a cursor until both windows 0 and 1 appear.
- Added `test_real_builder_emits_all_cascade_families`, which calls
  `assemble_arm_metric_bundle` with a real `SupplyRecipeSpec` catalog and real
  committed event objects instead of monkeypatching the builder.
- Added `tests/unit/test_economic_cascades_runner_e2e.py`, which builds the
  `cascade-production` assignment from `economic_cascades@1`, runs a real
  `SimulationRunner` V56 configuration for 96 ticks, and feeds the result and
  committed events through `assemble_arm_metric_bundle`; all eight cascade
  families emit.
- Refreshed the plan verification receipt counts (11989 full, 209 focused,
  26% focused coverage) and labeled the pre-fix full-coverage run.

## Prevention

- When a plan names composition-root wiring, assert it through the same factory
  the runtime uses; assigning `app.state` directly tests the route, not the
  wiring.
- Exercise every documented error code at the HTTP boundary, including TTL
  expiry, not only in the codec unit test.
- Keep at least one analysis fixture longer than one window whenever the
  contract has window-bound cursors or lag limits.
- Prefer at least one collector test with the real builder so a future builder
  signature change cannot be masked by a monkeypatch.
