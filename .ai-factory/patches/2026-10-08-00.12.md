# Clean ruff E501/I001 on knowledge-genealogy modules

**Date:** 2026-10-08 00:12
**Files:** src/agents/cognition/practical_knowledge.py, src/analysis/knowledge_genealogy.py, src/analysis/knowledge_genealogy_metrics.py, tests/unit/test_experiment_ap_knowledge_genealogy.py, tests/unit/test_knowledge_genealogy_metrics.py, tests/unit/test_practical_knowledge_carry.py, tests/unit/test_practical_knowledge_model.py, tests/unit/test_v3_knowledge_genealogy_regression.py
**Severity:** low

## Problem

`/aif-verify` reported non-blocking ruff findings on v3-13 genealogy paths: `E501` (line length > 88), plus auto-fixable `I001` / `RUF022` import/`__all__` ordering. Tests and contracts passed; style gate was the only warn.

## Root Cause

New genealogy modules and tests were written with long single-line conditions, asserts, and type annotations that exceeded the project's 88-column ruff limit. Import/`__all__` ordering was not run through `ruff check --fix` before commit.

## Solution

1. Ran `ruff check --fix` on genealogy source/test paths (imports + `__all__`).
2. Manually wrapped remaining `E501` lines (conditions, asserts, defaults, comments) without changing behavior.
3. Hoisted `known_entry_ids` once per audit row in the genealogy graph builder while wrapping the parent-edge check.

## Prevention

- Run `ruff check` on new/changed files before the docs/regression commit of a plan.
- Prefer early wraps for compound boolean guards and long enum defaults instead of post-hoc verify cleanup.
- Keep style fixes separate from behavioral commits when possible.
