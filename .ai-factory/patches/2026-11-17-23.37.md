# Missing verification suites for V4-28 scientific replication

**Date:** 2026-11-17 23:37
**Files:** `src/simulation/replication_paging.py`, `src/api/routes/replication.py`, `src/simulation/new_agent_initialization.py`, `src/simulation/runner.py`, `src/experiments/replication_publication.py`, `src/experiments/civilization_benchmark_evidence.py`, `tests/unit/test_replication_*.py` (8 new suites), `tests/unit/test_new_agent_blank_slate_guard.py`
**Severity:** medium

## Problem

`$aif-verify` on the completed `v4-28-replication` bundle found 11 partial tasks: the
implementation existed and the full suite was green, but the plan's required
task-specific evidence was absent. Missing suites covered runtime
recovery/abort/fork, store failure modes, paging, cursor/settings, publication
outcomes, and the 1/2/8/128 testimony sweep.

Writing those suites exposed four real implementation gaps:

- `BlankSlateStoreCounts` and the blank-slate deny/store lists did not include
  `replication_ledger`, so a newborn could not be proven free of copied
  replication state. Admission also asserted a zero-default count object instead
  of probing the real ledger.
- `experiments.replication_publication` had no `publish_replication_snapshot` /
  `build_replication_harvest_result`, so opt-in publication had no closed
  `published|disabled|missing|quota_exceeded|corrupt` receipt with an
  independent scientific status.
- The replication read routes reported every missing store as
  `publication_not_found`, so a missing run was mislabeled.
- `simulation.replication_paging.PAGE_LIMIT_MAX` was 200 while the documented
  contract and the HTTP layer allow 500.
- The read routes resolved the *latest* publication before decoding a cursor, so
  a cursor minted against publication A silently failed (or would have drifted)
  once publication B was published. The plan requires the cursor to select the
  immutable publication it was signed for.

## Root Cause

The feature was implemented breadth-first and validated with integration-level
smoke tests rather than the plan's per-task suites. Because every new module had
comfortable line coverage, the absent failure-path suites were invisible to a
green `pytest` run: coverage measured executed lines, not specified behaviors.

Two supporting causes:

- The blank-slate contract is enforced through several parallel enumerations
  (`SUBJECTIVE_COPY_DENY_LIST`, `BLANK_SLATE_SUBJECTIVE_STORES`,
  `BlankSlateStoreCounts`, `STORE_PROBE_PATHS` in the benchmark probe). Adding a
  new owner ledger requires updating all four; the feature updated none.
- `read_snapshot` collapses "no publication for this run" and "no such
  publication id" into one `replication_store_missing` code, so the route could
  not distinguish the two documented 404s without an explicit `publication_id`
  check.

## Solution

- Added eight focused suites (`test_replication_api_cursor`, `_settings`,
  `_paging`, `_store`, `_publication`, `_recovery`, `_fork_retirement`, plus a
  rewritten `_routes`) and extended `test_replication_end_to_end` with the
  1/2/8/128 count sweep. Each suite encodes the plan's behavior, not the
  implementation shape.
- Mixed the replication sidecar into all four blank-slate enumerations, added a
  content-count field, and made runner admission probe the actual ledger via
  `_blank_slate_counts` instead of trusting zero defaults. The benchmark probe
  counts real rows so an empty frozen ledger stays blank.
- Added `ReplicationHarvestResult`, `build_replication_harvest_result`, and
  `publish_replication_snapshot` with a closed status set, safe reason codes,
  and metadata-only logging.
- Split the two 404s in `_snapshot` using the requested `publication_id`.
- Raised the paging cap to the documented 500.
- Reordered `_page` so the cursor is verified before any store read, then used
  its bound `publication_id` to read that exact immutable publication; an
  explicit `publication_id` that disagrees with the cursor is rejected.
- Added a real fork/checkpoint round-trip (ledger survives export/restore, child
  installs its own state without mutating the source, foreign owner rejected)
  and a real retirement run proving `export_replication_ledgers` reads the
  frozen retired checkpoint; plus a two-publication HTTP repin test.

## Prevention

- Treat a plan's per-task "Tests / Acceptance / Verification" list as the
  acceptance contract. A green suite does not prove a task; the named files must
  exist.
- When adding an owner-scoped ledger, grep for every blank-slate enumeration and
  the benchmark `STORE_PROBE_PATHS` map, then extend the pinned tuple test in
  `test_new_agent_blank_slate_guard.py`.
- Prefer empty-vs-populated counting helpers for new frozen ledger types; a
  generic "opaque object is content" probe reports an empty ledger as content.
- Keep distinct public error codes distinct at the adapter boundary; do not let
  one internal code feed two documented HTTP meanings.
