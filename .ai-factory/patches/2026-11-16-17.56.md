# Intentional scientific tests were discarded by the runtime binding

**Date:** 2026-11-16 17:56
**Files:** src/simulation/agent_runtime.py, tests/unit/test_scientific_hypotheses_end_to_end.py, tests/unit/test_scientific_hypotheses_export.py
**Severity:** high

## Problem

A science-enabled agent never actually ran an intentional test in a real
`SimulationRunner` run. The `CognitiveLoop` selected an `Experiment` command at
the result boundary, but the engine received `Wait`; no `ExperimentResolved`
events were committed, the exported ledger stayed empty, and the completed-run
collector therefore never saw science evidence. Unit tests passed because they
called `CognitiveLoop.run()` directly or exercised `compile_scientific_test()` in
isolation.

Verification also exposed missing required deliverables: no Research UI panel
test, no `selection.test.ts` entry, no tests for the new ledger export helpers, a
broken owned-flag sentence in `docs/configuration.md`, and a frame cap (256) that
did not match the locked plan value (384).

## Root Cause

`AgentRuntime.bind_effective_command()` built the `ActionSubmission` from the
pre-loop `effective_command` it passed into `CognitiveLoop.complete()`. The loop
adjusts the local command inside `complete()` for loop-boundary modifiers
(speech frames such as `hyp_v1`, intentional experiments) and returns it as
`CognitiveLoopResult.command`, but the runtime ignored that field. The one-call
`prepare -> complete` path (`CognitiveLoop.run()`) returned the modified command,
so unit tests could not observe the loss.

## Solution

- Submit `loop_result.command` (re-validated with `require_agent_command`) instead
  of the pre-loop command, and derive `command_kind` from it. This makes every
  loop-boundary modifier effective in the runner, not only science.
- Rework the in-process end-to-end test to run the real `SimulationRunner` with
  `ImaginationMode.DISABLED` so the deterministic intention selects `Wait`; the
  loop now formulates and tests a hypothesis automatically, producing real
  `ExperimentResolved` events, real trial rows, and a retained `contradicted`
  hypothesis from `result.experiment_ledgers` (no `SimpleNamespace`).
- Add ledger export helper tests, a Research UI panel test, a selection test,
  docs parity assertions, and align `SCIENTIFIC_HYPOTHESIS_FRAME_MAX_CHARS` with
  the locked 384.

Logging stays metadata-only per project rules: no `[FIX]` payload logging was
added; `runtime_bind_complete` already records the final command kind.

## Prevention

- When a stage writes a command back into a result object, verify the submission
  path consumes that result field. Trace `prepare`/`bind`/`finalize` as well as
  the one-call `run()` path.
- End-to-end tests must assert committed events and runner-exported ledgers, not
  only loop results or hand-built result objects.
- Keep test files named in a plan's Files-to-Change table under an automated
  existence check; run the focused UI/unit suites named in the plan.
- Docs parity tests should assert owned/unowned counts, not only the catalog
  number.
