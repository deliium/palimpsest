# Medical-belief recovery digest, export availability, and strict owner-state validation

**Date:** 2026-11-23 00:53
**Files:** src/simulation/agent_runtime.py, src/simulation/runner.py, src/agents/cognition/medical_beliefs.py, src/agents/cognition/medical_beliefs_communication.py, src/simulation/medical_beliefs_config.py, src/simulation/runner_models.py, tests/unit/test_medical_beliefs_*.py
**Severity:** critical

## Problem

Verification of V4-35 found three substantive defects:

1. Every medical `finalization-command-v6` pending record was rejected after a
   process restart with `recovery_corrupt` and reason
   `medical_candidate_digest`.
2. `export_medical_belief_ledgers` synthesized an empty ledger for owners whose
   runtime was missing, so unavailable evidence was reported as intact and
   capture could claim `complete`.
3. The owner ledger accepted duplicate row IDs, duplicate seen roots, orphan
   outcome/interpretation rows, multiple attempts in one tick, and a dangling
   `open_attempt_id`, despite strict restore requirements.

Secondary drift: communication tie-breaks used lexical enum names instead of
declared order; missing checkpoint ledgers were accepted after processing; and
mode selection logged at `INFO` instead of `DEBUG`.

## Root Cause

The write path and the recovery path evolved separately. `_complete`
constructed `candidate_digest` inline and omitted the medical sidecar, while
`_v6_candidate_digest` re-included it on restore. The two paths also disagreed
about whether measurement is nested under replication. Export treated "no
ledger" and "no runtime" as the same state, and the ledger's constructor only
checked types and scalar bounds, not identity, references, or chronology.

## Solution

- Extracted `_candidate_digest(value, *, v6)` as the single fixed-order builder.
  The write path calls it with `v6` true whenever a medical candidate is
  present; restore calls it with `v6=True`. Legacy nesting is preserved when
  `v6` is false, so v1-v5 pending bytes and hashes are unchanged.
- Export now distinguishes an uninvoked active owner (loop enabled, empty
  ledger) from a missing/retired owner without checkpointed state, reporting
  the latter through `unavailable_owner_ids`.
- Ledger construction/restore validates row ownership, unique row IDs,
  at-most-one attempt per tick, exactly one outcome and interpretation per
  attempt, attempt references, chronology, bounded anchor/summary tables,
  duplicate seen roots, and `open_attempt_id` existence.
- Restore rejects a missing medical ledger once the checkpoint has processed an
  invocation.
- Communication ranking uses declared enum order, matching intervention choice.
- Medical activation logs moved to `DEBUG`.

## Prevention

- Build write and restore hashes from one shared function; never duplicate the
  candidate-digest formula.
- Regression tests must exercise the real `bind_effective_command` →
  `to_finalization_command` → encode → abort → restore path, not a fabricated
  integrity hash.
- Treat "no runtime state" and "intentionally empty owner state" as distinct
  research availability outcomes.
- For every bounded owner ledger, validate identity, references, and chronology
  at construction so strict codecs inherit the same checks.
- Add paired capture/no-capture twins when adding a detached research path.
