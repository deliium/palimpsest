# Ruff cleanup for V2 benchmark suite files

**Date:** 2026-10-04 21:38
**Files:** `src/experiments/benchmark_suite.py`, `src/experiments/benchmark_smoke.py`, `src/experiments/benchmark_scenarios/*`, related unit/compose tests
**Severity:** low

## Problem

`/aif-verify` reported 83 ruff findings on the V2 benchmark suite surface (mostly `E501`, plus unused imports, ambiguous en-dashes / multiplication signs, and import order). Style gate unclean despite green tests.

## Root Cause

Long invariant / composition strings and markdown table rows were written as single lines over the project's 88-column limit. Ambiguous Unicode punctuation (en dash, ×) was copied from prose. An unused `Callable` import remained after the builder protocol settled on `Protocol` + `Mapping`.

## Solution

- Wrapped long strings, calls, asserts, and `object.__setattr__` / `raise` lines to ≤88 columns
- Replaced the package docstring condition table with a bullet list that still names every `bench-*` id and locked condition tokens
- Normalized en dashes to ASCII hyphens and `×` to `x`
- Removed unused `Callable` import; dropped obsolete `# noqa: F401` on the concrete-builder import block
- Restored the unordered-condition-id registry test after an over-eager rewrite

## Prevention

- Run `uv run --frozen --python 3.12.14 ruff check` on the full changed-file set before marking verify green
- Prefer adjacent string literals or parenthesized multi-line calls for long invariant text instead of single 100+ character lines
- Avoid en dashes / special multiply signs in Python source comments and docstrings when RUF002/RUF003 are enabled
