# Clear V4-40 resilience verify ruff findings

**Date:** 2026-11-25 14:50
**Files:** src/simulation/resilience_evidence.py, tests/unit/test_resilience_capture.py, tests/unit/test_resilience_windows.py
**Severity:** low

## Problem

`/aif-verify` on `v4-40-resilience` reported non-blocking ruff failures on the
resilience surface (unused import, E501, unused loop name, import formatting)
and a soft Task 3 gap: no regression that `run_with_resilience_capture` avoids
whole-history `export_events()`.

## Root Cause

Static cleanup was skipped before the feature commits landed. Slotted
`WorldEngine` also makes instance-level `monkeypatch.setattr` on
`export_events` fail, so the planned raise-guard test needs a class patch.

## Solution

- Remove unused `MappingProxyType`; wrap long `require_stable_id` call; rename
  unused loop binding to `_name`.
- Reformat capture/windows unit tests to satisfy ruff line length and import
  sorting; drop unused `ResilienceEvidenceError` import.
- Add `test_capture_never_calls_whole_history_export_events` that patches
  `WorldEngine.export_events` on the class and still completes capture.

## Prevention

- Run `ruff check` on new/changed resilience modules before claiming static
  checks clean in the plan verification receipt.
- When monkeypatching slotted engine methods, patch the class, not the
  instance attribute.
