# Published compose start skipped the database image

**Date:** 2026-09-28 17:26
**Files:** tests/compose/test_stack.py, tests/unit/test_published_startup.py, .github/workflows/observer-image.yml, docs/development.md, .env.example
**Severity:** medium

## Problem

`tests/compose/test_stack.py` started Compose with `--pull never` without pulling the digest-pinned pgvector image first. On a machine that does not already have that image, the live stack fails even though the API image was built locally. The protocol job also omitted `libdbus-1-3`, `libegl1`, and `libxkbcommon0`, which the export stage installs for the official Linux editor. `PALIMPSEST_REVISION` was set by `./run-dev.sh` and reported by `GET /version`, but it was not named in the development docs or `.env.example`.

## Root Cause

`--pull never` was applied to the whole Compose project to stop the published API image from being pulled or rebuilt. That flag also refuses the database service. The browser test and the image workflow already pulled pgvector first; the older live fixture did not. The protocol job copied only the libraries that seemed necessary for a headless script, not the shared libraries the export stage already listed. The revision is a build argument rather than a host setting, so the docs update stopped at the startup URL.

## Solution

The live fixture logs `[FIX] database_image_pull image=%s` and runs `docker pull` on the compose database pin before `docker compose up --pull never`. The protocol job installs the three missing libraries and prints `INFO observer_protocol_libs_ok`. `docs/development.md` and a commented `.env.example` line name `PALIMPSEST_REVISION`. Unit checks read the fixture and the workflow so a later edit cannot drop the pull or the libraries.

## Prevention

- When a start uses `--pull never`, pull every image that is not the locally tagged one before that start.
- Keep the protocol job's shared libraries aligned with the export stage, and do not download the export template archive for the script-only job.
- Document image build arguments that appear in `GET /version`.
