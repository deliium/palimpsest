# Mypy `attr-defined` errors in V4-04 operation tests

**Date:** 2026-11-01 23:13
**Files:** tests/unit/test_organization_operations_filesystem.py, tests/unit/test_organization_operations_isolation.py, tests/unit/test_organization_operations_paging.py, tests/unit/test_organization_operations_runtime.py, tests/unit/test_organization_operations_end_to_end.py, tests/unit/test_organization_runtime.py
**Severity:** medium

## Problem

The documented static gate `uv run --frozen --python 3.12.14 mypy src tests` reported
eight `[attr-defined]` errors even though the V4-04 verification receipt recorded
the gate as passing:

- `tests/unit/test_organization_operations_filesystem.py:131`
- `tests/unit/test_organization_operations_isolation.py:126`
- `tests/unit/test_organization_operations_paging.py:122`, `:130`
- `tests/unit/test_organization_operations_runtime.py:147`, `:161`
- `tests/unit/test_organization_operations_end_to_end.py:283`
- `tests/unit/test_organization_runtime.py:237` (pre-existing at the V4-04 base)

## Root Cause

Two public contracts deliberately expose `object` payloads and the tests read
record fields without narrowing:

1. `OrganizationRowSelection.rows` and
   `SimulationRunnerResult.organization_*_ledgers` are typed as
   `tuple[object, ...]` because the paging port and the runner result are shared
   across several record families. Tests iterated them directly, so mypy rejected
   `row.operation_id`, `row.domain`, and `ledger.owner_id`.
2. A heterogeneous tuple splat
   (`(*row.controls, *row.admissions, *row.commitments)`) did not produce a usable
   element type, so mypy fell back to `object`.

The pre-existing error in `test_organization_runtime.py` came from the same
`tuple[object, ...]` contract and was never narrowed.

`mypy` is strict in `pyproject.toml`, so every one of these is a hard failure.

## Solution

Narrow at the test boundary without weakening any assertion and without changing
production contracts:

- `cast(tuple[OrganizationOperationRecord, ...], page.rows)` before reading
  operation fields.
- `cast(tuple[OrganizationOperationLedger, ...], exported)` before reading
  `owner_id`; the existing `type(...) is OrganizationOperationLedger` assertions
  were kept.
- `cast(tuple[OrganizationConceptLedger, ...], result.organization_concept_ledgers)`
  in the pre-existing V4-03 test.
- Replaced the heterogeneous splat with a nested loop over the three typed record
  families.

Production code, pins, and assertions were untouched.

## Prevention

- When a contract deliberately exposes `tuple[object, ...]`, narrow it with
  `typing.cast` (or `isinstance`) at the first read instead of indexing fields
  directly.
- Run `mypy src tests` before recording a verification receipt; a receipt must
  never claim a static gate passed without the current run.
- `tests/unit/test_organization_filesystem.py` already used
  `cast(OrganizationCandidateRecord, ...)`; follow that existing precedent for new
  paging and runner-result tests.
