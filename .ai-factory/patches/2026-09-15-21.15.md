# Complete WorldEngine Task 11 log assertion coverage

**Date:** 2026-09-15 21:15
**Files:** tests/unit/test_world_engine.py
**Severity:** low

## Problem

`/aif-verify` flagged Task 11 as partial: engine logging existed, but tests only
asserted `tick_committed` and absence of item name text. Missing coverage for
DEBUG outcome codes, WARN lifecycle/token misuse, ERROR `candidate_aborted`,
`PALIMPSEST_LOG_LEVEL` filtering, and broader payload redaction checks.

## Root Cause

Implementation prioritized determinism/replay proofs and docs for Task 11.
Logging instrumentation was already present in `simulation.engine`, but the
test plan's log-capture deliverable was only partially wired—enough for a
happy-path INFO smoke check, not the full diagnostic matrix.

## Solution

Extended `tests/unit/test_world_engine.py` with:

- DEBUG assertions for observation, admission, applied/deferred/duplicate
  resolution codes
- Exactly one INFO `tick_committed` per successful resolve under capture
- WARN `lifecycle_misuse` and `token_stale`
- ERROR `candidate_aborted` via in-try stale-token failure
- `PALIMPSEST_LOG_LEVEL=WARNING` filtering through `configure_logging`
- Redaction checks excluding names, observations, and private-state markers

No production logging changes were required.

## Prevention

- When a plan task lists log-capture requirements, add dedicated assertions in
  the same milestone as the instrumentation
- Prefer triggering abort paths that run inside the engine's candidate `try`
  (stale token), not pre-try `TypeError` guards that skip ERROR logging
- Treat bootstrap `registrations=<count>` as allowed metadata; assert against
  registration/content dumps, not the count field name
