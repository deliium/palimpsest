# V4-31 competing theories: verification gaps and unbounded publication

**Date:** 2026-11-20 22:20
**Files:** `src/experiments/competing_theories_publication.py`, `src/analysis/competing_theories_analysis.py`, `src/analysis/competing_theories_models.py`, `src/experiments/competing_theories_completed_run.py`, `src/simulation/runner.py`, `src/persistence/competing_theories_filesystem.py`, `clients/research-ui/src/views/CompetingTheoriesPanel.svelte`, `clients/research-ui/src/views/CompetingTheoriesPanel.test.ts`, `tests/integration/test_competing_theories_runner.py`, `tests/unit/test_competing_theories_*.py`, `docs/*`, `.ai-factory/*`
**Severity:** high

## Problem

`$aif-verify` on the completed `v4-31-competing-theories` bundle found the feature
green under focused tests but missing several plan-mandated behaviors:

- `pnpm check` failed with three TypeScript errors in the Research UI panel, and
  the required panel test did not exist.
- Publication composed every analysis row without whole-window truncation or the
  documented 8 MiB envelope, so a large run could raise or write an oversized
  artifact instead of `quota_exceeded`.
- Recovery decoded the pending finalization payload but never compared it with
  the durable record identity.
- Hit/miss classification treated `brier == 0` as a hit, so a correct categorical
  prediction with a non-zero Brier numerator was counted as a failure.
- The controlled popular-inaccurate/accurate-minority fixture and the real
  runner→store→authorized-GET integration lane were absent.

## Root Cause

The implementation was validated breadth-first: each module had focused happy-path
tests and the full suite was green, so missing acceptance-level behaviors were
invisible. Three supporting causes:

- Publication treated the snapshot as an unbounded projection rather than a
  bounded, window-admitted artifact.
- Recovery trusted the decoded payload; the record/payload identity invariant was
  never encoded.
- Performance scoring reused Brier-zero as a proxy for a categorical hit instead
  of retaining the frozen `hit` flag per claim.

## Solution

- Added the Research UI panel test, fixed optional-property handling and
  `ApiClientError` usage, separated disabled/missing states, and added explicit
  social/predictive axis labels.
- Reworked publication to admit whole newest windows plus claim dependencies,
  enforce section-row and 8 MiB bounds, report omitted windows, and raise
  `quota_exceeded` when even the newest window cannot fit. Prediction rows are now
  per case/claim with frozen probability vectors; failure rows project observed
  misses only.
- Compared recovered commands with the pending record's codec, run, owner, tick,
  invocation and integrity identity before installing owner state.
- Retained `hits` per claim in completed-run facts and scored hits/failures from
  that flag; the paired loss difference is suppressed below three pairs.
- Added the controlled 4-supporters/1-minority analysis fixture, a real
  40-tick runner→publication→store→authorized multi-page GET integration test,
  disjoint recipient cohorts converging on different rivals, addressed
  support/teaching receipts from a real communication arm, real outbox
  crash/recovery coverage, and publication bound tests.
- Added the denied/replaced-command negative control, the exact encoded
  `thy_v1` frame equality assertion, the social-switch-preserves-failure-history
  case, and removed the unused local-first helper. Clarified the plan and docs:
  a qualifying social alternative is adopted before the one-time local prior.

## Prevention

- Treat each phase's "Tests / Acceptance / Verification" list as the contract; a
  green suite does not prove a task when the named file is missing.
- Any canonical artifact must enforce both per-section and total-byte bounds in
  the composer, not only at construction time.
- Recovery must compare durable record identity with the decoded payload before
  installing subjective state.
- Score categorical predictions from the frozen outcome flag, never from a
  secondary loss proxy.
