# Same-tick exchange accept could not see the offer

**Date:** 2026-10-12 12:37
**Files:** src/world/_operations.py, src/agents/cognition/loop.py, src/agents/cognition/subjective_value.py, src/analysis/exchange_functions_metrics.py, tests/unit/test_experiment_av.py, tests/unit/test_exchange_function_metrics.py, tests/unit/test_exchange_functions.py, tests/unit/test_subjective_value.py
**Severity:** medium

## Problem

A `NegotiateExchange` accept submitted after an offer in the same tick was rejected. Experiment AV therefore could not assert a v40 swap hash or scripted later-trade and quote arms. Ruff also reported unsorted slots, unused imports, and long lines in the new v3-19 modules. `tests/unit/test_exchange_function_metrics.py` was missing.

## Root Cause

`prepare_action_batch` judged the opening rule against the tick's starting state. The offer updated the working state only after that check, so the accept still saw no live proposal. The batch already reapplies operations in submission order; the first rule check ignored that order for exchange.

## Solution

For `negotiate_exchange`, the opening rule now uses the working state. A DEBUG line `[FIX] exchange_rule_state` records the actor and act. Experiment AV submits the offer before the accept in one tick, compares the channel-off event digest with a v40 baseline and with the profile flag on, and classifies a later trade and two homogeneous completions from the engine history. The metrics test covers an empty harvest and the three families. Ruff findings in the new modules were cleared.

## Prevention

- When a plan says a later command in the same tick must see an earlier mutation, assert that pair in one `resolve_tick`, not across two ticks.
- Keep the opening rule and `apply_operation` on the same state for commands whose validity depends on earlier commands in the batch.
- Run ruff on the new test modules before verification.
