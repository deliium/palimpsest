# Close Task 9 episodic-memory proof gaps after verify WARN

**Date:** 2026-09-21 12:44
**Files:** tests/unit/test_v1_episodic_memory_ownership.py, tests/unit/test_v1_memory_retrieval_scoring.py, tests/unit/test_v1_memory_service_logging.py, .ai-factory/ROADMAP.md
**Severity:** medium

## Problem

`/aif-verify` on `v1-episodic-memory-traces` marked Task 9 only partially proven: foreign-owner adversarial ranking, explicit six-component scoring coverage, and metadata-only service log capture were thin or missing. Roadmap M3 still read as not started despite delivered cognition/memory work.

## Root Cause

Implementation and commit plan treated Task 9 as done once core ownership/scoring/decay suites existed, without mapping each verify checklist item to a named assertion. Roadmap status was not updated when M3 cognition/memory deliverables landed ahead of remaining LLM composition work.

## Solution

- Added ownership proofs that foreign traces with adversarially higher scores never leak into another owner's ranked results, plus atomic batch conflict rejection.
- Extended scoring tests so all six weighted components, disabled-component behavior, and context/social ranking are asserted with fixed vectors and policies.
- Added caplog tests that service DEBUG/WARN lines stay on the metadata allowlist (scope, ticks, counts, reason codes) and never include trace/query/vector content.
- Moved M3 to in progress with delivered vs remaining bullets so verify no longer flags a stale milestone.

## Prevention

- Before marking a “prove X” plan task complete, grep the task deliverable list and require one named test per bullet (or an explicit deferral note).
- When `/aif-verify` reports partial proofs, prefer filling the named gaps over re-running the full suite alone.
- Update roadmap milestone status in the same change set that lands the milestone’s primary deliverable, even if later sub-bullets remain open.
