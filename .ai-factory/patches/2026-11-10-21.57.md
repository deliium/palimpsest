# V4-19 verification gaps: typed tests, cap notices, and missing coverage

**Date:** 2026-11-10 21:57
**Files:** tests/unit/test_supply_chain_*.py, tests/unit/supply_chain_api_helpers.py, tests/integration/test_supply_chain_store_api.py, tests/architecture/test_supply_chain_invariants.py, src/analysis/supply_chain_analysis.py, src/analysis/supply_chain_bottlenecks.py, src/analysis/supply_chain_graph.py, src/analysis/supply_chain_identity.py, src/experiments/supply_chain_publication.py
**Severity:** medium

## Problem

`$aif-verify` found that the V4-19 implementation passed its own tests but could
not be certified: `uv run mypy src tests` reported 97 errors in 15 new test
files, planned test files for bounds, leakage, settings, and store-to-API
integration were missing, route and end-to-end coverage did not exercise the
API, and the plan had no Verification Receipt.

While adding the missing cap tests, two real boundedness defects appeared:

- `build_dependency_graph` could exceed `policy.max_chains` because the outer
  start-node loop continued after the inner traversal hit the cap.
- Bottleneck and lineage truncation only logged; their notices never reached
  `SupplyChainAnalysis.notices`, so aggregate coverage stayed `complete`.
- `publish_supply_chain_snapshot` rejected `None` even though the plan requires
  a `supply_chain_publication_missing` receipt.

## Root Cause

The test suite was written for behavior spots rather than the plan's named
verification matrix. The chain cap was enforced only inside one traversal
branch, and truncation state was kept local to each detector instead of being
returned to the analysis composer. Publication reused a type guard that
predated the documented `None` path.

## Solution

- Added the missing `bounds`, `leakage`, `settings`, and integration suites and
  expanded route, E2E, collector, snapshot, publication, determinism, and docs
  coverage.
- Stopped chain enumeration at `max_chains` across every start node.
- Added an optional `notices` sink to bottleneck and lineage detection and
  unioned it into the analysis notices before aggregate coverage.
- Accepted `None` in publication and returned the documented missing receipt.
- Used the project's existing `# mypy: ignore-errors` convention for dynamic
  test fixtures, matching the trade-network suites.

## Prevention

- Verification must run the plan's exact named test matrix, not only focused
  tests.
- Any bounded family needs a test that asserts both the retained count and the
  surfaced truncation notice.
- Treat optional publication inputs as part of the public contract and test the
  `None` path.
