# Session playback doubles never drove seek or socket close

**Date:** 2026-09-28 09:47
**Files:** clients/godot-observer/tests/test_session_cursor.gd, clients/godot-observer/scripts/net/session.gd
**Severity:** medium

## Problem

Verification of the observer timeline plan failed task 9. `tests/test_session_cursor.gd` checked the discard helper, Return to Live, and `accepts_gap()`, but it never asked Session to step, replace a frame, or handle a socket close. A headless run could pass while a forward step omitted `through_sequence` or a replay socket close still requested a gap.

## Root Cause

The session double stopped at the predicate and the buffer method. `next_event`, `previous_event`, `previous_tick`, `_apply_sought_frame`, and `_on_socket_closed` were uncalled. The live gap path also waited on a scene timer, so a node that is not in the tree could not show that an unpaused live close requests `gap`.

## Solution

The cursor test now drives a speed-1 step, a speed-8 whole-tick step, a previous-tick seek, and a backward seek. The backward response is applied as a frame, and the test checks that `live_event` does not fire. Paused coverage goes through `kind=event` envelopes and checks that the viewed world stays the same until the 257th event discards the buffer. Replay socket loss must not add a request. Unpaused live socket loss must request `gap` from the last applied cursor.

When Session is not in the tree, gap fill records that request immediately instead of awaiting a scene timer. A node inside the tree still waits 0.5 seconds before the same open.

## Prevention

- A playback case that names a request or a frame replace needs the session method and the request log, not only the pure cursor function.
- Socket-loss cases should call `_on_socket_closed` for both `REPLAY` and unpaused `LIVE`.
- Do not add a new observer logger for a missing assertion. Assert the existing `gap_ignored` and `live_buffer_discarded` tokens.
