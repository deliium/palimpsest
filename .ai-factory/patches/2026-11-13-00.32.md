## Problem

Post-implementation verification found several defects that the existing test suite did not catch:

- `ruff` failed with four B009 errors in the accounting route and paging helpers.
- Record-condition `share_milli` was approximately 1000 for every condition because it was computed from the condition's own quantity histogram; there was no `insufficient_samples` state.
- `ArtifactModified` and `ArtifactAnnotated` were silently ignored by detached record reconstruction.
- The filesystem store enforced only a per-payload byte limit, not a cumulative publication quota.
- The experiment collector never passed token-only owner exports into the analysis, so owner and alignment families were always missing in real runs.
- Unfiltered multi-window paging filtered by row id only and skipped rows from later windows.
- Accounting debt candidates were appended to `EventObservedReference` inputs and raised `evidence_invalid_record`; valuations were read from a nonexistent `rows` attribute.
- Analytical entry tokens used the `acco-` owner prefix instead of `acce-`.
- Snapshot summary coverage omitted conditions, flows, and counterparties, and `truncated` was copied rather than recomputed.

## Root Cause

The feature was implemented and tested per task in isolation, but cross-task integration was not exercised:

- Each detector was unit-tested with claims only, so the condition-share formula and record-only analysis path were never compared with the documented contract.
- The evidence bridge unit test checked the candidate helper, not the loop wiring that partitions observed references from prior agreements.
- The store test checked publication-count quota, not cumulative bytes.
- The collector path and multi-window cursor path were not covered by the E2E.
- Some plan interfaces conflicted with committed event data (artifact events do not carry relation content), which made record-only analytical entries impossible without a forbidden event-schema change.

## Solution

- Replaced constant `getattr` calls with direct attribute access and removed unused route helpers.
- Made paging keys include `window_index`, so cursors compare the full `(window_index, id)` order.
- Added `availability` to condition rows and snapshots; condition shares now use the window total; fewer than four entries in a window is `insufficient_samples`.
- Added `ArtifactModified` and `ArtifactAnnotated` record rows for coverage and condition evidence.
- Enforced cumulative publication byte quota in the filesystem store.
- Added `accounting_owner_rows_from_result` and wired the collector to pass token-only owner exports.
- Partitioned accounting evidence candidates by type and passed `prior_agreements` separately.
- Read real `SubjectiveValuationLedger.kind_rows`/`judgment_rows`.
- Added `acce-` analytical entry tokens.
- Added condition/flow/counterparty coverage to snapshot summaries and derived `truncated` from partial coverage.
- Documented that analytical entries derive from committed `acc_v1` claims because committed artifact events do not carry relation content; record metadata still drives coverage and condition evidence.

## Prevention

- Add at least one integration test per cross-task wiring seam: collector → analysis, loop → evidence, snapshot → API, and paging across multiple windows.
- Do not infer event payload contents from the plan; check the actual event DTO before claiming analysis can reconstruct them.
- Exercise quota tests with cumulative state, not only a single oversized artifact.
- Keep token prefixes in a shared contract module and assert them in detection tests.
- Run the full static gate and focused accounting suite before filling a verification receipt.
