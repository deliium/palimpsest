# Observer persistence attachment assumed `app.state.settings`

**Date:** 2026-10-26 01:22
**Files:** `src/api/app.py`, `tests/unit/test_observer_population_replay.py`
**Severity:** medium

## Problem

`tests/unit/test_observer_population_replay.py::test_app_attaches_the_persistence_replay_context_source`
failed with:

```text
AttributeError: 'State' object has no attribute 'settings'
```

The test constructs a bare `FastAPI()` and calls
`api.app._attach_persistence_services(app, object())`, which is a valid
attachment helper usage. The failure appeared after the Task 7 civilization
change started reading `app.state.settings` unconditionally. The Task 16
acceptance command did not include this earlier observer test, so the regression
slipped past the 552-test gate.

## Root Cause

The civilization-service attachment was inserted into
`_attach_persistence_services` after `create_app` began setting
`app.state.settings`. The helper implicitly assumed every caller follows that
full composition path, but the helper is also exercised directly by tests with a
minimal FastAPI application. Reading `app.state.settings` eagerly turned an
optional composition input into a hard requirement for all persistence-only
attach paths.

## Solution

- Read settings defensively with `getattr(app.state, "settings", None)`.
- Skip only the optional civilization-service attachment when settings are
  absent; all existing persistence/replay/observer attachment still runs.
- Emit a metadata-only DEBUG record with `reason_code="settings_unavailable"`.
- Keep the existing broad catch around optional civilization storage attach so a
  configured-but-unavailable root cannot break base observation.
- Add `test_persistence_services_skip_optional_civilization_without_settings`
  to assert the helper still attaches observer services while leaving the
  optional civilization service unset.

## Prevention

- Private composition helpers should degrade gracefully when optional
  higher-level state is missing; do not assume the test adapter mirrors the full
  `create_app` setup.
- When adding a new optional service to `_attach_persistence_services`, run the
  existing observer/generational unit suites, not only the new feature suite.
- Include `tests/unit/test_observer_population_replay.py` in later
  authority/compatibility gates so direct-helper attachment stays covered.
