# Hypothesis coverage and AI Factory context artifacts

**Date:** 2026-09-14 21:40
**Files:** tests/unit/test_reproducibility_contracts.py, tests/unit/test_world_agent_contracts.py, tests/unit/test_subjective_state_contracts.py, .ai-factory/DESCRIPTION.md, .ai-factory/ARCHITECTURE.md, .ai-factory/RULES.md, .ai-factory/ROADMAP.md, .ai-factory/rules/base.md, .ai-factory/plans/feature-v1-project-foundation.md
**Severity:** low

## Problem

Verification reported non-blocking warnings: no Hypothesis `@given` tests despite
acceptance criteria, missing `.ai-factory` context artifacts (DESCRIPTION,
ARCHITECTURE, RULES, ROADMAP), and integration checks not executed in the prior
verify pass.

## Root Cause

Foundation work declared Hypothesis and documented architecture in `docs/`, but
property-based tests and agent context files under `.ai-factory/` were never
created. Integration tests are opt-in and were skipped without a disposable DB.

## Solution

- Added Hypothesis properties for stream determinism, scope non-aliasing, global
  RNG isolation, observation detachment, and cross-owner memory rejection.
- Added `.ai-factory` DESCRIPTION, ARCHITECTURE, RULES, ROADMAP, and rules/base
  aligned with the implemented foundation; linked the plan to milestone M1.
- Executed live `pytest -m integration` against a disposable pgvector database
  (3 passed).

## Prevention

- When acceptance criteria mention a test style (Hypothesis), add at least one
  property test in the same milestone.
- Create `.ai-factory` context artifacts during foundation setup, not only
  contributor `docs/`.
- Run opt-in integration markers before treating verify as fully green.
