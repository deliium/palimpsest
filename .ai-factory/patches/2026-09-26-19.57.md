# Prospective selection and audit logs omitted required fields

**Date:** 2026-09-26 19:57
**Files:** src/agents/cognition/prospective.py, src/agents/cognition/prospective_selection.py, src/agents/cognition/imagination.py, src/simulation/agent_runtime.py, src/simulation/runner.py, tests/unit/test_prospective_imagination.py
**Severity:** low

## Problem

Verification of the bounded prospective plan found the ranking and audit log lines incomplete. `prospective_llm_selection` omitted `selected_count` and `token_count`, fallback stayed at DEBUG, and budget skips used logger `agents.cognition.imagination`. The runtime append line omitted `expanded_count`, `pruned_count`, and `timeout_hit`.

## Root Cause

The log strings were written from the fields that were convenient at the call site. The plan's field list was treated as a description of the audit object, not as the required line. Budget stops were logged next to the check in `imagination.py` instead of on `agents.cognition.prospective_selection`.

## Solution

One helper, `log_prospective_llm_selection`, writes the DEBUG line with owner, tick, candidate count, selected count, token count, and `fallback_used`, and writes WARNING `prospective_llm_fallback reason_code=...` when fallback is set. Budget skips call that helper without loading the LLM facade. Append and export logs now include expanded count, pruned count, and whether the timeout hit. Tests assert those tokens and that prompt text stays out of the line.

## Prevention

When a plan names a logger and a field list, assert that exact line in the unit test that exercises the branch. Keep one helper so budget skips and provider failures cannot drift to a second format.
